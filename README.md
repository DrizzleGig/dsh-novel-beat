# dsh-novel-beat｜拍板

**你的故事，你来决定走向。**

「拍板」是一款面向小说创作者的 DeepSeek Harness 剧情决策插件。人物要不要暴露秘密、关系会走向何方、重要物品落到谁手里——遇到会改变故事走向的岔路，AI 停下来给出选择，由你拍板。

决定之后，拍板把选择、已确立的设定和未完成的承诺记进本书账本。写得久了，能回看；改变主意时，先看影响，再回退重写。

**v0.9.0：可信账本。** 这一版把真实版本、时间线、章末体检、搜索和重写工单带到「拍板台」，换上朱批纸本界面，也为其他插件提供只读服务 `novelBeat`。

AI 帮你展开故事，你掌握故事的方向。

## v0.9.0：每个决定，都有来路可查

### 可信账本：改了什么，账本有自己的版本

长篇写作里，最怕的是你正准备改一条旧决定，账本却已经被另一轮写作更新了。

v0.9.0 为账本加入真实版本 `book.revision`：每次成功提交账本变更，版本递增一次。侧栏回退或改选会核对你看到的版本；如果账本已经变化，就返回 `revision-conflict`，这次操作不会截断正文。刷新、重新看过影响后，再决定怎么改。

版本号记录的是账本的变化，不是存过多少张快照。拍板、段落登记和回退等提交事件带有 `commitId = <书名>#<revision>`，方便其他插件确认自己收到的是哪一次变更。

### 朱批纸本：地图、时间线、体检，各看一件事

右栏「拍板台」改成暖纸、墨字与朱砂的纸本风格，浅色与深色跟随宿主。章号、决策状态条和「定 / 待 / 旧」印章，把已落账、待处理和旧账分开呈现。

朱砂标记当前、拍板与回退风险，青玉表示已落账或检查通过，琥珀提醒还有事情待处理。

| 视图 | 你想知道的事 |
|---|---|
| **地图** | 这本书定了什么？哪一章还有岔路没回答？ |
| **时间线** | 什么时候拍过板、登记过正文、退过旧线？ |
| **体检** | 这一章还有哪些决定、段落或承诺需要处理？ |

搜索就在地图页。找一条旧决定、回看一次回退、检查当前章，不必再从整段聊天记录里翻起。

### 时间线：把一路改过的决定串起来

登记岔路、拍板、登记段落、回退、核对、豁免和待复核等记录，会汇成可回看的历史。可以按类型筛选，沿日期查看，点条目回到对应章节。

回退条目可以打开已保存的旧线，看看当时写过什么。时间线展示的是账本里已有的记录；没有登记过的手动改文，不会凭空变成历史事件。

### 章末体检：下一章之前，看看还欠什么

写完一章，切到「体检」，先看阻断、提醒和提示，共 10 项，再逐项处理：

- 还有没有未答的决策，或自定义答案尚未补齐结构化变化；
- 已经拍板的决定，有没有登记对应正文段落；
- 有没有等待作者确认的设定变化；
- 登记段落后，是否还需要做续写检查；
- 已登记段落是否与当前正文发生漂移，正文里有没有尚未登记的区间；
- 有没有到期未处理的承诺与义务；
- 本章是否因前文改动被标记为待复核，旧账是否缺少正文锚点。

**打开体检只读取账本与正文，不会替你修文，也不会把问题自动标成已解决。** 找不到或读不到正文时，会明确提示，并跳过正文漂移与未登记区间检查；这不等于正文已经通过检查。

体检帮你找结构上的遗漏，不评价文笔，也不能代替通读正文。

### 搜索：找回一句设定背后的决定

在地图页输入人物名、秘密、物品或一段关键词，搜索已记录的**决策、设定和义务**。结果按类别列出：点决策可以回到对应章并选中，点设定或义务可以定位相关章节。

比如，你想知道「药园里的灵草后来定归谁了」，可以从相关关键词找回当时的选择与设定。搜索查的是剧情账本，不是整本小说的全文。

### 重写工单：换了方向，续写也要带着新决定

回退或改选之后，「继续写」不再只给 AI 一句笼统的续写指令。插件会根据当前记录整理重写工单，包括：

- **已改选**：这次改的是哪条决定、选了什么；
- **必须发生 / 不得出现**：新走向要落实什么，有哪些明确禁项；
- **必须保持 / 相关设定**：仍需保留的事实，以及这次选择涉及的变化；
- **上一段末尾**：从哪里接着写。

工单按已有信息生成，并优先保留改选和关键约束。点「继续写」后，它会交回当前写作会话；宿主续写入口不可用时，可以复制工单手动发送。

正文仍由你和 AI 完成。工单提供重写依据，不会自动修好后面所有章节。

### 只读服务 novelBeat：可以协作，决定权仍在作者

v0.9.0 提供 `identity / getStatus / getRevision / getCanon / getArtifact / onDidCommit`，供其他插件识别能力、读取状态和设定、核对版本、查看段落凭据，并订阅成功提交后的事件。

这组接口负责读取与通知，不提供改账或替作者拍板的方法。编排插件可以据此知道「这一章是否还欠一次确认」，却不能通过它直接改掉你的选择。

**没有 conductor，拍板仍然可以独立工作。** conductor 是可选的协作方，不是安装或使用前提。接口细节见下方「技术信息」。

## 上一版能力：v0.8 的右栏拍板台，继续保留

- **按章看决策**：展开章节，查看当前选择、其他走向和对应的设定变化。
- **回退前看影响**：确认前列出将截断的正文字数、作废的段落、撤回的设定和重开的后续决策，按你的实际账本计算。
- **回退与改选**：对具备有效正文锚点的决定，确认后回退，或选择另一条走向重新落账。
- **旧线留档**：侧栏回退默认先保存正文与账本快照，之后可以只读查看旧线。
- **后续章节待复核**：可以把后续章节标记为待复核，提醒自己检查人物动机、关系与因果；标记本身不改那些章节的正文。

这些能力在 v0.9.0 中继续使用，并接上了真实版本检查、时间线和重写工单。

## 快速开始

不用改变原来的写作方式，也不用一直开着。

### 1. 安装 v0.9.0

需要 DeepSeek Harness。插件可以独立安装，不要求同时安装其他小说插件。

**从 npm 安装 0.9.0：**

```bash
dsh plugin --profile web add dsh-novel-beat@0.9.0
```

**或从 GitHub 固定到 v0.9.0 标签：**

```bash
dsh plugin --profile web add "github:DrizzleGig/dsh-novel-beat#v0.9.0"
```

这里的 `web` 是示例 profile 名，请换成你实际使用的 profile；桌面端若使用 `desktop`，就将 `web` 改为 `desktop`。装好后重启 Harness。

> 不带版本号的 npm 命令会安装当时的 latest；GitHub `main` 与本地源码是开发版，都不等同于固定的 `v0.9.0` 标签。

### 2. 开启拍板

默认关闭。在要处理重要剧情的章节开始前，输入：

```text
/beat on
```

也可以点输入框旁的「拍板」按钮。默认保护的正文目录是 `正文`；如果你的正文放在其他目录，先用 `/beat body 路径` 添加。

### 3. 在岔路口做决定

像平常一样告诉 AI 写第几章、往下写。遇到关键剧情节点时，拍板给出 2–4 个有区别的走向及其代价。你确认方向，AI 接着写这一段，登记正文，再做结构核对。

第一次使用，可以从涉及秘密、人物关系或重要物品的一场戏开始。

### 4. 打开右栏「拍板台」

在右侧插件栏打开「拍板台」：地图看决定，时间线看历史，体检看本章待办。写到一半改变主意时，先查看影响预览，再确认回退或改选。

关闭拍板后，右栏仍可查看历史，但不能在侧栏执行回退或改选。

## 一个写作场景

你让 AI 继续写秘境夺宝：主角发现一株即将成熟的灵草，泥土里却还残留着禁制。有人先来过，而灵药成熟后又会引来附近的修士。

拍板把岔路交给你：

- **先探禁制，再谋灵药**：多花时间与符箓，换取对风险的了解。
- **布下后手，伺机取药**：争取机缘，也可能与禁制的主人结下因果。
- **暂避锋芒，记下位置**：保住底牌，接受灵药可能被别人拿走。
- **借他人之手，坐观其变**：借势探路，也承担暴露行踪的风险。

你选择暂避。正文从留下标记、隐匿气息接着写；确认并落账后，「主角没有取药」「禁制仍在」就成了下一章需要遵守的事实。

后来你想改成「先探禁制」。在地图里找到这条决定，先看回退会影响哪些正文、段落和设定，保留快照，再确认改选。后续章节可以标成待复核；新的重写工单交回会话，AI 从新的方向继续。

**决定由你下，AI 负责把代价写出来。**

## 日常怎么用

拍板记两类重要信息：**已经确立的事实（Canon）**，以及**还没完成的承诺与义务（Obligations）**。开新章前看一遍，写完后再核对，帮助你维护长篇的连续性。

| 你说的话 | 拍板能帮你处理什么 |
|---|---|
| 这个秘密暂时不能让所有人知道。 | 把知情范围的变化列为需要确认的剧情决定。 |
| 这两个人到底要不要合作？ | 展开不同关系走向及其代价。 |
| 上一章答应的事，这章该兑现了吗？ | 检查尚未完成的义务。 |
| 下一章之前，看看之前定过什么。 | 汇总已确立的事实与待处理事项。 |
| 这章写完了，看看还有哪里没落账。 | 结合段落登记、结构核对与章末体检检查遗漏。 |

### 作者侧命令

| 命令 | 作用 |
|---|---|
| `/beat on` / `/beat off` | 开关拍板模式；关闭后撤下本插件的工具、技能与闸门，侧栏保留历史查看。 |
| `/beat status` | 查看模式、受保护目录和当前章待处理的决策状态。 |
| `/beat body <路径>` | 添加一个受保护目录，默认目录为 `正文`。 |
| `/beat body reset` | 将受保护目录恢复为默认的 `正文`。 |
| `/beat list [章]` | 列出本章或指定章已登记的段落、字数与关联决策。 |
| `/beat revert [段落 ID]` | 回退指定段落及其后续段落；不传 ID 时处理当前章最后一段。请从段落列表取得实际 ID。 |
| `/beat fork <要决定什么>` | 主动插入一条岔路，让模型先把它整理为决策点再提问。 |

回退会改变正文，日常改选建议从侧栏进入，先看影响再确认。命令回退另有 `!` 重新定位确认标记，适用于正文已经改动、且你确认要按登记原文重新定位的情况；只有能唯一定位时才可继续，找不到或出现多处仍会拒绝。使用前应先备份并核对目标。

开启拍板后，输入框上方还有一条段落状态栏，可以查看当前章、已登记段落和最后一段字数，并使用「重写这一段」「刷新」。它与右栏拍板台可以同时使用。

## 适合谁，以及它的边界

适合用 AI 辅助写作、又想自己掌握关键剧情的作者；也适合人物多、关系复杂、伏笔多的长篇连载。故事简单、只想直接生成一段正文时，不必为了使用插件而增加流程。

- **正文由你和 AI 写。** 拍板不接管正文生成；作者确认的回退会截断受影响正文，这与生成新正文是两回事。
- **关键选择由作者确认。** 模型的猜测不能直接当成已确认设定，待答决策仍需在对话里完成；侧栏改选用于调整已有选择。
- **体检关注结构。** 它不评价文笔、文学水平或人物是否鲜活，也不保证找出所有错误。
- **改选后仍需检查后文。** 待复核标记和重写工单提供依据，不会自动改好所有后续章节。
- **旧线用于查看。** 本版不提供一键撤销回退、自动恢复整本书或多条剧情路线随意切换。
- **本版不提供多书切换面板、决策依赖图、批量拍板或决策地图导出。**

## 数据与安全

账本保存在本地工作区：

```text
<工作区>/.dsh-novel-beat/<书名>/
├── book.json     # 剧情决策账本（含 revisions[] 历史记录）
└── rewinds/      # 侧栏回退时保存的正文与账本快照
```

v0.9.0 继续使用 **`schemaVersion: 2`**，可直接打开 **v0.7 / v0.8 账本**；0.6 的 v1 账本在读取时迁移。账本主要包含 decisions / canon / obligations / chapters / segments / revisions / requests / tasks / forks / audit，并加入真实账本版本 `revision`。

- **本地保存**：账本与快照留在工作区。插件自身不主动上传正文；写作会话中的模型请求仍由 DSH 和你配置的模型服务处理。
- **默认留快照**：侧栏回退默认保存正文与账本快照；可以取消勾选，但建议保留。关闭快照后，不能指望这次回退仍有旧线可查。
- **先核对再回退**：侧栏检查正文锚点、段落内容和账本版本。旧账没有有效锚点，或正文已发生漂移时，可能只能查看，不能直接安全回退。
- **只读查看不等于恢复**：旧线供查阅与找回文字参考，不会自动覆盖当前正文或账本。
- **备份整个项目**：升级或大规模调整剧情前，建议同时备份正文和 `.dsh-novel-beat` 目录，保留账本与相关快照。

快照给你留下回看旧线的机会，日常备份仍要自己保存。

## 常见问题

### 拍板会自动写小说吗？

不会。它帮助识别剧情岔路、记录选择和核对结构。正文仍由你与 AI 在写作会话中完成；「继续写」只是把重写工单交回会话。

### v0.9.0 能直接打开 v0.7 / v0.8 的账本吗？

可以，账本格式仍是 `schemaVersion: 2`。旧账里缺少正文锚点的决策可以查看，但兼容账本不代表每条旧决定都能回退。升级前建议备份正文和账本目录。

### 关闭拍板后，还能看以前的决定吗？

可以。右栏保留历史查看，侧栏回退和改选会禁用。需要继续受控写作时，再用 `/beat on` 开启。

### 我已经写了几十章，还能改以前的决定吗？

能否回退取决于那条决定的正文锚点与当前文件状态。先在地图中查看影响预览；可执行时再确认回退或改选，并检查被标记为待复核的后续章节。

### 回退后，原来的正文还能找回来吗？

保留了快照，就可以通过旧线查看回退前的文字。回退会实际截断当前正文，旧线也不是一键恢复按钮；重要修改前请另做备份。

### 为什么提示 revision-conflict？

侧栏看到的账本版本已经过期，可能是你打开面板后又有一轮写作或记账。这次回退或改选会停止，正文不动。刷新面板，重新查看影响后再操作。

### 体检没有阻断，就代表这一章完全没问题吗？

不是。体检只核对已记录的信息与可读取的正文结构。提醒、待复核和旧账缺锚点仍需处理；如果提示正文不可读，正文相关检查并未完成。它也不评价文笔与情绪效果。

### 搜索能搜整本正文吗？

不能。当前搜索范围是账本中的决策、设定和义务。正文全文请使用你自己的编辑器搜索。

### 一定要装 conductor 或其他小说插件吗？

不用。拍板独立可用；其他插件可以通过只读接口和提交事件协作，缺席时不影响拍板本身的功能。

测试数字取自本版 [CHANGELOG](./CHANGELOG.md) 的发布检查记录；该记录同时列有 `npm run check` 与 `git diff --check` 通过。

### 工具与集成

11 个工具分别是 `beat_plan`、`beat_next`、`beat_segment`、`beat_revert`、`beat_fork`、`beat_list`、`beat_decide`、`beat_gate`、`beat_compile`、`beat_verify`、`beat_adjust`。参数和调用条件见 [工具文档](./docs/tools.md)。

`novelBeat` 的本版只读集成入口：

| 接口 | 用途 |
|---|---|
| `identity()` | 获取插件身份、版本与服务能力。 |
| `getStatus()` | 获取章节状态与待处理事项。 |
| `getRevision()` | 获取真实账本版本与最近历史记录信息。 |
| `getCanon()` | 获取已确立的事实与义务。 |
| `getArtifact()` | 查询段落或决策等产物凭据。 |
| `onDidCommit()` | 订阅成功提交后的事件。 |

新读取接口不会为读取而写账本；遇到更早的 v1 账本，仅在内存中迁移。历史兼容入口 `query()` / `resolveBook()` 仍可能触发旧账本落盘迁移，新集成应优先使用上述接口。

开发者升级时还需区分：

- `schemaVersion` 是数据格式，`book.revision` 是变更版本，`revisions[]` 是历史记录，三者不能互换。
- `query().version` 保留原来的账本格式含义；插件版本请读取 `identity().version`。
- `beat_segment` 返回的 `revision` 在 v0.9.0 中改为整数账本版本，原快照对象改放在 `revisionRecord`。
- 侧栏回退 / 改选通过 `expectedRevision` 检查版本冲突；不要据此假定所有工具都支持 `expected_revision`。
- 面板「体检」是只读检查，与写作流程里会记录核对状态的 `beat_verify` 不是同一个入口。

更多信息见 [集成契约](./docs/contract.md)、[编排适配说明](./docs/conductor-adapter.md)、[架构说明](./docs/architecture.md) 与 [v0.8 实现说明](./docs/v0.8.0-implementation.md)。
