**关键剧情由作者决定，长篇账本负责留痕。**

拍板识别会改变故事走向的分叉，记录选定方向、相关事实与后续义务。它服务于作者已有的写作流程，不替作者生成整章正文。

**版本口径：** 本文件描述 **0.12.2**。发布渠道与版本号以官方 npm registry 和 GitHub 标签为准；正文里的测试数字是本地实跑结果，不是 npm 上的安装状态。

## 本版本（v0.12.2）

0.12.0 重制右栏「拍板台」：分镜卡网格、分段页签、胶囊筛选、四格详情（你当时怎么定的 / 为什么停在这里 / 走向 A / 走向 B）、六套可切换底色（宣纸/米白/灰白/青瓷/淡雾/夜墨）；状态差分等账本表达改成故事语言，界面不再出现内部键与数字增减。功能块与信息架构不变，0.11.0 的作者自定拍板与 voice 写法基线保留。

### 空白 / 自己写：作者永远有一条自己的路

提问卡的最后一行固定是宿主的自由输入行。作者可以不选 A/B/C，直接写下自己的走向：

1. 原文立即入账（标记「作者自定」），右栏的地图、时间线与决策详情都能看到原文。
2. 模型把这段原话整理成结构化状态变化（`changes`），落账后这条决策才算完成。
3. 补完之前不能继续写正文——闸门会以 `PENDING_STRUCTURED_CHANGES` 拦下，避免"写了但账本没记"。

插件不替你编造状态：作者的决定不等于程序伪造正文证据。

### voice 影响选项内容，而不只是排序

已确认的文风档案会作为**选项写法基线**随工具结果交给模型：同一岔路在不同文风下，选项的切入点、语气与代价感应当不同，而不是换近义词。

- 判定可用的条件：voice 只读接口报告 `voice.brief` 能力、存在 `status: 'confirmed'` 且带版本的档案、简报回执确认同一档案版本。**不要求 voice 提供会话开关**（0.2.2 没有）。
- 作者可以关掉：`/beat voice off` 强制中性；`/beat voice auto` 恢复跟随（默认）。
- 文风只影响措辞：不改写既定事实、不伪造证据、不把风格差异写成难度或智商差异。
- 没有服务、没有已确认档案、超时、旧档：全部平滑降级为中性，提问与写入都不阻塞。

### 右栏「拍板台」：审查、回顾、回退

右栏保留原有信息块：**决策地图、时间线、体检、决策详情、回退、旧线**，外加搜索与筛选。0.11.0 只重做视觉与交互（字体阶梯、语义色、间距与层级、浅/暗双主题、焦点与动效），不重构信息架构，也不在侧栏放选择按钮或自定义输入框——决策在对话里完成。

### 段落循环（默认关闭）

`DSH_NOVEL_BEAT_SEGMENT_LOOP=1` 才注册 `beat_append` / `beat_finish`。一段一个自然段，段后必须检查并绑定最新段 hash；章末确定性合并，artifact 只写 `.dsh-novel-beat/<书名>/`，不写章节文件。**已知边界：** loop 章目前仍走旧的候选口径（不带 v3 证据闸门），只适合在隔离工作区试用；补强排在发布之后，默认关闭。

## 上一版能力：v0.9 起就有的右栏

### 先看影响，再改旧决定

回退前查看涉及的正文字数、段落、事实和后续决定；确认后才执行，并可保留正文与账本快照。面板打开后若账本已变化，会停止本次操作，要求刷新并重新审查。

### 时间线：这本书做过什么，一条线看完

按时间回看决策、段落登记、回退、体检和待复核记录。筛选与查看不改账本。

### 章末体检：写完一章，先看有没有漏

检查待答决策、正文登记、设定确认、段落核对、承诺和待复核章节。结果为阻断、提醒或提示；体检只报告可读到的数据，不自动修稿或标记解决。读不到正文时会说明跳过相关检查。

### 搜索：找回一句设定背后的决定

按人物、秘密、物品或关键词搜索剧情账本中的决定、事实与承诺；不搜索正文全文。

### 换方向之后，让 AI 知道新方向

回退后整理改动、新方向、不能沿用的旧事实、仍有效的设定与续写位置，交回当前对话。它是写作简报，不代写正文，也不自动改后续章节。

### 朱批纸本：右栏像一本稿纸

暖纸、墨字与朱砂色标记；0.11.0 换成衬线正文 + 无衬线 UI、更清晰的字号阶梯与语义色（朱砂=待你定/危险，青玉=已落账，赭石=提醒，墨灰=旧账）。

| 视图 | 你想知道的事 |
|---|---|
| **地图** | 已定下什么？哪里还有待处理决定？哪一拍是作者自己写的？ |
| **时间线** | 何时拍板、登记正文、回退或体检？ |
| **体检** | 本章还有哪些事实、段落或承诺需要复核？ |

## 上一版能力：v0.8 的右栏拍板台，继续保留

- **按章查看决策**：查看已选方向、其他走向和事实变化。
- **回退前看影响**：列出正文、段落、事实与后续决定的影响。
- **回退与旧线**：确认后回退；快照可供只读查看。
- **后续章节待复核**：标记需要重新检查的章节，不改正文。
- **与 0.9 衔接**：继续提供时间线、体检与重写简报。

## 快速开始

拍板默认关闭。安装后，在重要剧情节点启用即可。

### 1. 安装 v0.12.2

需要 DeepSeek Harness。拍板可以独立安装，其他小说插件均为可选。

**从 npm 安装：**

```bash
dsh plugin --profile web add dsh-novel-beat@0.12.2
```

**或固定到 GitHub 标签：**

```bash
dsh plugin --profile web add "github:DrizzleGig/dsh-novel-beat#v0.12.2"
```

web 是示例 profile；桌面端按实际 profile 替换。安装后重启 Harness。不带版本号会跟随 npm latest；GitHub main 与本地源码不是固定发布版。

### 2. 开启拍板

在重要章节开始前输入：

```text
/beat on
```

可用 `/beat off` 关闭，`/beat status` 查看状态。默认保护 正文 目录；正文在别处时先用 `/beat body <路径>` 添加。

### 3. 在岔路口做决定

照常描述章节与情节。拍板会把关键走向及代价交给作者确认；事实和承诺随后进入账本。

- 选 A/B/C 里的一条，直接点。
- 都不满意：在提问卡最后一行写下自己的走向，提交即可。
- 想换说法：让拍板按你已确认的文风写选项（`/beat voice auto`），或关掉（`/beat voice off`）。

### 4. 打开右栏「拍板台」

右栏用于查看地图、时间线、体检、历史和回退影响。它不提供选择按钮，也不提供自定义输入框；决策与自定义回答都在对话里完成。

## 一个写作场景

秘境中的灵草即将成熟，泥土还留有禁制痕迹，取药可能暴露行踪。对话会呈现几种方向及其代价：

- **先探禁制**：多花时间与符箓，换取风险信息。
- **布下后手**：争取机缘，也承担与禁制主人结因果的风险。
- **暂避锋芒**：保住底牌，接受灵草可能被取走。
- **作者自定**：直接在最后一行写下"先退出去，守三天，等别人先踩雷"。

若装了 voice 并确认了档案，同样三条选项的措辞会带上你的文风；作者自定的原文会原样进入账本，右栏标「作者自定」。选择完成后，右侧供作者审查事实、时间线与回退影响。

## 日常怎么用

开章前核对已确定事实和未兑现承诺，写后检查遗漏。拍板记录剧情，不替作者判断作品质量。

| 你说的话 | 拍板能帮你处理什么 |
|---|---|
| 这个秘密暂时不能让所有人知道。 | 标出知情范围的剧情决定。 |
| 这两个人要不要合作？ | 展示关系走向及代价。 |
| 上章答应的事，这章该兑现了吗？ | 核对未完成承诺。 |
| 下一章前看看定过什么。 | 汇总事实与待办。 |
| 这章写完了，检查有没有漏账。 | 检查段落、决策与承诺记录。 |

### 作者侧命令

| 命令 | 作用 |
|---|---|
| `/beat on` / `/beat off` | 开关拍板模式。 |
| `/beat status` | 查看状态、正文目录和本章待办。 |
| `/beat voice auto` / `/beat voice off` | 选项写法跟随已确认文风 / 强制中性（默认 auto）。 |
| `/beat body <路径>` | 添加受保护的正文目录。 |
| `/beat body reset` | 恢复默认 正文 目录。 |
| `/beat list [章]` | 查看段落、字数与关联决定。 |
| `/beat revert [段号]` | 回退指定段及后续段落；省略时处理本章最后一段。 |
| `/beat fork <要决定什么>` | 请求对话整理一个新的决定点。 |

回退会改正文。命令可用 ! 重新定位：按登记原文定位，只有唯一命中才继续；找不到或多处匹配均拒绝。先备份并核对目标。段落状态栏显示章节、登记段落和字数，并可用「重写这一段」「刷新」；可与右栏并开。

## 适合谁，以及它的边界

适合希望自己掌握关键剧情、同时借助 AI 写长篇的作者。短篇或单段生成不必增加这套流程。

- **正文由作者与 AI 写。** 拍板记录选择和核对结果。
- **剧情方向由作者确认。** 未答决定不能视为已确认事实。
- **自定义拍板要补结构化变化。** 作者写的是走向，状态变化由模型整理；补完前不能继续写。
- **文风可能降级。** 没装 voice、没确认档案、接口超时都会回到中性；面板会显示原因。
- **体检关注结构。** 不评价文笔，也不保证发现所有问题。
- **回退后需检查后文。** 待复核标记和简报不自动修稿。
- **功能边界明确。** 不提供一键撤销回退、整本书自动恢复、多条剧情线随意切换、多书面板、决策依赖图、批量拍板或地图导出。

## 系列插件与搭配建议

以下五包各自独立、均为可选。beat 当前只读消费 voice 的已确认档案；与 kit、fade、fanfic、conductor 的共享写入尚未接入，表中是按创作需要选择的建议。

| 包 | 定位 | 适合搭配的情形 |
|---|---|---|
| `dsh-novel-kit` | 小说工作台，系列主入口。 | 希望从一个工作台组织小说工具与章节流程时。 |
| `dsh-novel-fade` | 长篇记忆，沉淀并回查跨章信息。 | 连载篇幅长、需要减少设定遗忘时。 |
| `dsh-novel-voice` | 创作风格档案与风格参考。 | 需要维持叙述表达一致性时。beat 0.11.0 读取其已确认档案作为选项写法基线；voice 0.2.2 没有会话开关，beat 以"已确认档案"作为同意信号，并提供 `/beat voice off` 关闭。 |
| `dsh-novel-fanfic` | 同人 canon 依据，区分原著事实与本作设定。 | 同人创作需要核对原著依据时。 |
| `dsh-novel-conductor` | 以 runbook 编排章节步骤和等待点。 | 希望明确一章的推进顺序、作者确认点和验收凭据时。 |

可按需组合：kit 与 conductor 面向统一入口和章节编排；fade 与 voice 面向长篇连续性和表达一致性；fanfic 可与记忆或风格工具并用。以上是职责层面的搭配建议，不表示当前已有自动交接或共享写入。

## 数据与安全

账本保存在本地工作区：

```text
<工作区>/.dsh-novel-beat/<书名>/
├── book.json         # 剧情决策账本（schemaVersion 3）
├── transactions/     # 成对回退的事务日志与快照
├── rewinds/          # 旧线快照（只读查看）
└── quarantine.json   # 恢复失败时的只读隔离标记（如出现）
```

0.11.0 使用 `schemaVersion` 3；账本兼容 v0.7 / v0.8，v0.6 及更早账本会在首次打开时迁移，迁移前留存 `book.json.bak`。升级或大规模改剧情前，备份项目和账本目录。

- **本地保存**：插件不主动上传正文；模型请求仍由 DSH 与已配置服务处理。
- **成对事务**：回退把正文与账本当一对处理：先写事务日志和双快照，再原子替换并回读 hash；恢复失败会隔离该书，只读查看、禁止继续写。
- **快照**：侧栏回退默认保存正文与账本快照；可以取消，但取消后不能指望这次回退仍有旧线可查。
- **先核对再回退**：正文锚点或版本变化可能使操作无法安全执行。
- **查看不等于恢复**：旧线不会自动覆盖当前正文或账本。
- **单独备份**：升级或大规模改剧情前，备份项目和账本目录。

## 常见问题

### 拍板会自动写小说吗？

不会。它记录决策并整理核对信息；正文仍由作者与 AI 写作。

### 我写了自定义走向，为什么还不能继续写？

因为状态变化还没落账。模型需要先把你的原话整理成结构化 `changes`，否则会出现"正文写了、账本没记"的半状态。闸门会以 `PENDING_STRUCTURED_CHANGES` 拦下，落账后自动放行。

### 为什么选项看起来还是中性的？

三种可能：没装 voice、没有已确认档案、或你关掉了跟随（`/beat voice off`）。`/beat voice` 会显示当前状态与原因。文风只影响措辞，不会改变事实与代价。

### v0.11.0 能直接打开 v0.9 的账本吗？

可以。v0.7 / v0.8 账本兼容；v0.6 及更早版本首次打开时迁移。缺少正文锚点的旧记录可能只能查看；升级前备份正文和账本。

### 关闭拍板后，还能看以前的决定吗？

可以。关闭拍板后历史仍可查看；侧栏回退与改选会禁用。

### 我已经写了几十章，还能改以前的决定吗？

先看正文锚点、账本版本和影响。能否安全回退取决于这些信息是否仍有效。

### 回退后，原来的正文还能找回来吗？

保留快照时可查看旧线；旧线不是自动恢复按钮，重要修改前另做备份。

### 为什么提示「看到的是旧版本」？

说明面板打开后账本又有变化。刷新并重新审查，不要沿用过期预览。

### 体检没有阻断，就代表这一章完全没问题吗？

不是。体检只检查它能读取且已登记的信息，不评价文笔或情绪效果。

### 搜索能搜整本正文吗？

不能。搜索范围是账本中的决定、事实与承诺。

### 一定要装别的插件吗？

不需要。拍板可独立运行；系列包的定位与搭配场景见「系列插件与搭配建议」。

### 工具与集成

默认 11 个工具：`beat_plan`、`beat_next`、`beat_segment`、`beat_revert`、`beat_fork`、`beat_list`、`beat_decide`、`beat_gate`、`beat_compile`、`beat_verify`、`beat_adjust`。`DSH_NOVEL_BEAT_SEGMENT_LOOP=1` 时额外注册 `beat_append`、`beat_finish`（默认关闭）。

`novelBeat` 只读集成入口：

| 接口 | 用途 |
|---|---|
| `identity()` | 获取插件身份、版本与服务能力。 |
| `getStatus()` | 获取章节状态与待处理事项。 |
| `getRevision()` | 获取账本版本与最近历史信息。 |
| `getCanon()` | 获取已确立事实与义务。 |
| `getArtifact()` | 查询段落或决策凭据。 |
| `onDidCommit()` | 订阅成功提交事件。 |

### 数据模型与不变量

- **账本**：`book.json` 含 `schemaVersion: 3`、单调递增的 `revision`、`decisions[]`、`segments[]`、`canon`、`obligations[]`、`requests[]`、`revisions[]` 与审计记录；旧账本按 v1→v2→v3 逐版迁移。
- **决策**：候选必须带 `gate`（稳定 `entity/key/from/to` + EvidenceRef）与选项六要素（`action`、`costs`、`outcomes`、`informationGain`、`risks`、`changes`）。闸门拒绝白名单外状态键、陈旧或错位证据、no-op、重复差分、作者已决定和假分叉。
- **证据**：正文 EvidenceRef 绑定文件 SHA-256、UTF-16 offset 与逐字 quote；拍板后只允许在原文末尾追加。证据失效时，面板回退与改选都会被禁用，remote 直接调用也会被重新校验拦下。
- **作者自定**：`chosen.source` 取 `proposed` / `author-edited` / `author-custom`；自定义原文进入 `answerText` 与 `pendingCustom`，落账后写 `chosen.custom` 与字段级 diff。
- **回退事务**：`transactions/` 记录 prepared → committed，正文与账本成对快照、暂存校验、原子替换、回读 hash；冲突不写事务副作用。
- **文风基线**：`voiceGuidance` 随 `beat_plan` / `beat_next` / `beat_segment` / `beat_append` / `beat_verify` 结果返回，含 `styleText`（≤1200 字）、`profileId`、`profileVersion`、`revision`、`digest`；不可用时带 `reason` 与中性说明。
- **段落循环**：章节 `writingMode: 'segment-loop'`，段 `seq` 连续、单自然段、SHA-256 绑定；合并按 `seq` 升序与固定分隔符拼接，`mergeReceipt` 只对其绑定的段版本有效。

### 兼容与降级

- 0.11.0 只向 schema v3 追加可选字段，旧账本无这些字段时按"中性/未接入"处理，不触发迁移失败。
- voice 不可用、超时、旧档、无确认档案：`voiceGuidance.available=false`，选项按中性生成，流程不中断。
- 段落循环工具默认不注册；`segment-loop` 章与 legacy 章不得混用同一种写法。
- 面板只读；`beat_verify` 是写作流程中的核对入口，会记录核对状态。

更多信息见 [工具文档](./docs/tools.md)、[集成契约](./docs/contract.md)、[编排适配说明](./docs/conductor-adapter.md) 与 [v0.8 实现说明](./docs/v0.8.0-implementation.md)。
