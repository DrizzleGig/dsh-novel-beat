# dsh-novel-beat｜拍板

**你的故事，你来决定走向。**

## 故事由你决定，每个选择都有迹可循

「拍板」是一款面向小说创作者的剧情决策插件，让作者真正掌控整本小说的剧情走向。

人物命运如何发展，关系会走向何方，秘密何时揭晓，故事最终通往怎样的结局——重要选择由你决定，而不是交给 AI 自行发挥。

拍板不仅帮助你决定接下来发生什么，还让你随时回看整本书做过的剧情选择。你可以查看已经确定的走向，了解其他可能；也可以在改变主意时，预览剧情调整的影响，安全回退并重新选择。

**写下每一个决定，也保留每一种可能。**

AI 帮你展开故事，你掌握故事的方向。

## v0.8 新功能：右栏拍板台

以前，剧情决定更多发生在聊天记录里。写得越久，做过的选择越多，想重新检查某个决定就越不方便。

v0.8 把这些决定集中到右栏「拍板台」。

### 决策地图

打开右栏，按章节查看全书决策：每章有几个岔路、各自选了什么、对应哪段正文。点开一条，能看到当前选择、其他走向，以及当时改了哪些设定。

真实账本里，一部 12 章的小说会显示 12 章、35 个决策、5 段已落段落、6,759 字正文。哪一章还有待拍板、哪一章是旧账、哪一章需要复核，都在列表上标出来。

### 回退前先看影响

改过去的决定，后面的剧情也要跟着动。拍板不会让你在不知道后果的情况下直接回退。

确认前先给一张影响单：

- 会删多少字正文；
- 会作废哪些已登记段落；
- 会撤回哪些已确立的设定；
- 会重开哪些后续决策。

例如：删 1,222 字、作废 2 段、撤回 4 条设定、重开 1 个后续决策。数字先摆出来，再决定要不要退。

### 安全回退与旧线

确认回退时，插件默认先把正文和账本各存一份快照，再把正文截断到目标决策的起点，作废后面的段落，倒序撤回设定，把后续决策重新打开。

回退完成后可以点「查看旧线」，只读查看回退前的正文。旧线是留档，不是一键撤销：它帮你找回当时写过什么，但不会自动把整本书恢复成旧版本。

### 改选与待复核

在侧栏直接选另一个走向，不用翻聊天记录。确认后插件按同一套事务回退，再把新选择重新落账；旧选择、旧凭据和旧 revision 都保留，不抹历史。

如果这次改动会影响后面的章节，可以在确认页勾选「把后续章节标记为待复核」。它只加一个「待复核」标记，不动那些章节的正文，提醒你回头检查人物动机、关系、因果和设定。

### 继续写

回退完成后点「继续写」，插件会把续写指令发回当前会话，让 AI 从新的分叉继续写。宿主没有可用的续写入口时，面板保留「复制续写指令」，可以手动发。

拍板负责把决定交还给作者，不负责替作者完成正文。

## 快速开始

不用改变原来的写作方式，也不用一直开着。

### 1. 安装

```bash
dsh plugin --profile web add dsh-novel-beat
```

或直接从 GitHub 安装：

```bash
dsh plugin --profile web add github:DrizzleGig/dsh-novel-beat
```

装好后重启 Harness。插件可独立使用，不需要其他写作插件。

> 从 GitHub `main` 或本地源码安装的是开发版；账本格式是 `schemaVersion 2`，兼容 v0.7 账本。

### 2. 开启

默认关闭。在要处理重要剧情的章节开始前：

```text
/beat on
```

也可以点输入框旁边的「拍板」按钮。

### 3. 写作，在岔路口拍板

像平常一样告诉 AI 写第几章、往下写。AI 正常推进正文；遇到会改变故事走向的节点时，「拍板」停下来，给出 2–4 个走向和各自的代价。你选定方向，AI 接着写这一段落账，写完再做结构核对。

第一次用，可以拿一章涉及秘密、人物关系或重要物品的剧情试试。

### 4. 打开右栏「拍板台」

进入右侧插件栏，打开「拍板台」。在这里查看全书的决策地图、回看已做出的选择、检查其他走向，或者对需要调整的剧情做安全回退。

关闭拍板后，右栏仍然可以查看历史决策，但不能执行回退或改选。

## 一个真实的写作场景

你让 AI 继续写秘境夺宝这一场：主角随宗门队伍进入上古药园，发现一株即将成熟的「凝元草」——能稳固筑基根基，对灵根普通的修士是不可多得的机缘。

AI 写到这里停了下来。药草周围看着没人，泥土下却残留着极淡的禁制纹路，旁边还有一截被剑气削断的阵旗：有人先来过，布下的禁制也没散干净。而灵药成熟时灵气外溢，附近修士迟早察觉。宗门有先到先得的规矩，却也禁止弟子私毁同门或他派修士的禁制。

**A｜先探禁制，再谋灵药**：借纸人和阵盘摸清残留，确认没有埋伏再动手。多耗符箓与时间，可能错过灵药成熟。

**B｜布下后手，伺机取药**：暗中布下隔绝阵法与退路，成熟即采。收益最大；但若禁制另有主人，可能结下因果、引来筑基修士追踪。

**C｜暂避锋芒，记下位置**：留个隐蔽标记先退，等别人探路再判断。保住性命与底牌，也可能眼看机缘落入他人之手。

**D｜借他人之手，坐观其变**：引其他修士接近药园，观察禁制反应与守药人的手段。能借势降风险，一旦失手就暴露行踪、卷入两派恩怨。

你选 C。AI 从「主角如何留下标记、如何隐匿气息」接着写；这一段落账，下一章之前它还记得主角没取药、禁制还在、灵药随时可能被别人拿走。

**决定由你下，AI 负责把代价写出来。**

### 写到一半想改主意

写到第 10 章，你觉得第 8 章「主角是否暴露底牌」当初选得太保守，想从「藏」改成「露一半」。

打开拍板台，第 8 章有 3 个决策。点开那一条，先看影响：删 1,222 字、作废 2 段、撤回 4 条设定、重开 1 个后续决策。确认回退，旧线快照保存；在新选择里点「露一半」，再把第 9、10 章标成「待复核」，最后点「继续写」。

故事换了方向，旧路还在，后面要补的地方也一目了然。

## 怎么用它

「拍板」落在两个时刻：写作中停下来问你，写完后替你核对。

### 你大概会这样说

| 你说的话 | 拍板会做什么 |
|---|---|
| 这章主角要拿到一件重要物品，后续怎么发展还没定。 | 找出会改变走向的节点，给出不同选择。 |
| 这个秘密暂时不能让所有人知道。 | 把「谁知道」当成需要确认的剧情变化。 |
| 这两个人到底要不要合作？ | 给出不同的人物关系走向及其后续影响。 |
| 上一章答应的事，这章要兑现吗？ | 提醒还没完成的承诺和义务。 |
| 这章写完了，帮我看看有没有漏掉之前定的事。 | 核对已决定的剧情变化有没有落实。 |
| 下一章之前，先看看还有哪些事没解决。 | 呈现已确立的事实和未完成的义务。 |

### 四件事

**关键剧情决策**：识别可能改变故事走向的事件——谁知道了秘密、谁站到哪一边、谁欠了谁、重要物品到了谁手里、哪个承诺要到期、哪段关系变了。每个节点给 2–4 个真不同的走向，不是把同一个选择换几种说法。

**全书剧情账本**：你确认的决定进本书共用的账本，主要记两类——已经确立的事实（Canon，如「凝元草仍在药园，主角只留了标记」）和尚未完成的义务（Obligations，如「禁制的主人迟早会查到来过药园的人」）。

**下一章提醒**：开新章前呈现这本书已确立的事实和待处理的义务，避免人物突然知道不该知道的事，也避免约定过的内容无故消失。

**写后核对**：正文完成后检查关键变化有没有发生、秘密知情状态对不对、人物关系与物品归属有没有结构性矛盾、承诺有没有被错误忽略或提前结清。发现问题只指出不一致，改不改由你定。

### 作者侧命令

| 命令 | 作用 |
|---|---|
| `/beat on` / `/beat off` | 开关拍板模式（关闭后工具、技能、闸门全部撤下） |
| `/beat status` | 看模式、受保护目录、当前章还有几个岔路没问 |
| `/beat body [路径\|reset]` | 增删受保护的正文目录（默认 `正文`） |
| `/beat list [章]` | 列本章已登记的段落（段号 / 字数 / 挂了哪些决策） |
| `/beat revert [段号]` | 退这一段重写（不传段号=最后一段，它后面的段一起作废；正文被改过时加 `!` 表示按原文定位照退） |
| `/beat fork <要决定什么>` | 自己插一条岔路，模型必须先把它写成决策点再往下问 |

输入框上方还有一条拍板条（只在 `拍板：开` 时出现）：左边显示「第 N 章 · K 段 · 最后一段 X 字」，右边两个按钮——「重写这一段」和「刷新」。v0.8 的右栏「拍板台」是更完整的决策地图，两者可以同时使用。

## 适合谁

**适合**：日更网文作者（更新频繁，要维护连续性）；长篇连载作者（人多、关系复杂、伏笔多）；用 AI 辅助但不想让 AI 擅自决定关键剧情的作者；有明确剧情规划、想自己掌握方向的作者；写到一半想改早期决定、又不想丢掉旧线的作者。

**不太适合**：只想要 AI 直接生成正文的用户；只写简单日常、不涉及重要剧情变化的用户；希望插件自动评价文笔、情绪、节奏和人物塑造的用户。短篇也能用，但故事简单时开它的必要性不高。

## 它不做什么

- **不写正文**：不接管正文生成模型和写作流程。
- **不替作者决定**：只提供走向，选择权在你。
- **不擅自改 Canon**：模型猜测不能直接变成已确立的剧情事实。
- **不评价文笔**：写后核对只做结构，不判断句子是否优美、人物是否鲜活。
- **不保证发现所有错误**：它依赖已记录的剧情事实和结构化信息，替代不了通读正文。
- **不保证改选后所有后续章节自动改好**：它只能作废受影响的已登记段落、撤回设定、重开后续决策，并提醒你复核。
- **不强制全程开启**：默认关闭，需要时开。
- **不依赖其他插件**：可独立安装使用。

它不是替你管理整本小说的作者代理，只是把那些容易被 AI 擅自决定、又容易在长篇里遗忘的事情交还给你。

## 数据与安全

拍板使用 `book.json` 保存小说的剧情决策账本。

```text
<工作区>/.dsh-novel-beat/<书名>/book.json
```

v0.8 使用 `schemaVersion: 2`，兼容 v0.7 的账本格式。账本包含 decisions / canon / obligations / chapters / segments / revisions / requests / tasks / forks / audit；回退快照在 `rewinds/` 下。

关于数据处理：

- 账本和快照都在本地工作区，插件本身不联网、不上传正文。
- 回退前默认保存正文与账本快照；确认页可以取消勾选，但我们建议保留。
- 可以查看回退前保留的旧线，但它只是只读留档，不是一键撤销。
- 关闭拍板后，仍然可以查看历史决策，但不能通过侧栏执行回退。
- 大规模调整剧情前，建议先备份正文和 `book.json`。

**重要提醒：** 快照是为了给作者留下回看旧线的机会，并不意味着可以免除日常备份。请妥善保存自己的小说文件。

## 常见问题

### Q1：拍板会自动写小说吗？

不会。拍板负责识别重要剧情岔路、展示决策并记录作者选择。正文仍然由你和 AI 在写作会话中完成。

### Q2：我已经写了几十章，还能改变以前的决定吗？

可以。打开拍板台，找到对应决策，查看回退影响。确认回退后，可以选择另一个走向。

但请注意，早期决定可能影响大量后续内容，应先检查影响预览。

### Q3：回退后，原来的正文会消失吗？

默认会先保存正文与账本快照，你可以查看旧线。回退会按照影响预览处理当前正文和已登记段落，不应把它理解为无损切换剧情路线。

### Q4：改变早期决定后，后面的章节怎么办？

可以将后续章节标记为待复核。你需要根据新的剧情方向检查相关正文、人物关系和设定。

### Q5：关闭拍板后，还能查看以前的决策吗？

可以。关闭后，拍板台仍然提供历史决策查看，但不能执行回退。

### Q6：v0.8 能否直接使用 v0.7 的账本？

可以。v0.8 的 schemaVersion 2 兼容 v0.7 的账本格式。

### Q7：拍板会评价我的文笔吗？

不会。拍板关注的是剧情决策，不负责评价语言风格、表达质量或文学水平。

### 设计原则

- 作者确认优先于模型推测。
- 已确认的剧情事实不能被随意改变。
- 未完成的剧情义务需要持续保留。
- 写作中的实时决策与写后结构核对分开处理。
- 结构核对不越权评价文学质量。
