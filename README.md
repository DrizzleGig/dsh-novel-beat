# dsh-novel-beat｜拍板

**你的故事，你来决定走向。**

写长篇小说，最怕的不是写不出来，而是 AI 替你把关键剧情定了：谁背叛、秘密先告诉谁、主角走哪条路、这段关系要不要断。

「拍板」把这些岔路留给你。

AI 写到会改变故事走向的地方，会停下来，把 2–4 条路和各自的代价摆出来。你选一条，它接着写；选过的路记进这本书的账本，下一章还记得，写完还能核对。

写得久了，想改早期的决定，也不用提心吊胆：先看会动到多少字、哪些设定、哪些后文，再决定要不要退；旧稿留着，想找还能找回来。

**v0.9.0 起：更清楚地看着这本书。** 右栏换成了「朱批纸本」，新增时间线、章末体检、搜索和重写工单。账本也学会了记「这是第几版」——如果在你动手之前，这本书已经被另一轮写作改过，拍板会先停下来，不会把正文改到一半。0.9.1 只修了这份说明，功能与 0.9.0 相同。

AI 帮你展开故事，你掌握故事的方向。

## 本版本（v0.9.2，2026-11-21）

- **装了故事总控时，拍板模式由它决定**：总控关着 → `beat_*` 不可用、L1 技能与 L3 写入拦截都撤下（哪怕 `/beat on` 过）；总控开着 → 可用（哪怕没 `/beat on`）。没装故事总控时，照旧按 `/beat on|off`。
- 接管时 L1 技能、L2 系统提示、L3 写入 guard 三层一起收放；只改内存，不写书目录里的持久开关。
- `/beat status` 会直接说「本会话开 / 关，/cue on 才对」。
- 工具参数 schema 守卫进 `npm test`。


## v0.9.0：每个决定，都有来路可查

### 先看影响，再改旧决定

写到第 10 章，发现第 8 章那个「藏还是露」选窄了。打开右栏，点开那条决定，先看它会动到什么：删多少字、作废哪几段、撤回哪些设定、后面哪些决定要重新想。

确认之后才会回退；回退前默认留一份正文和账本快照。旧稿不会凭空消失，想回看当时怎么写，点「查看旧线」。

如果你打开面板之后，另一边又写了一轮，拍板会提醒你「看到的是旧版本」；这次回退先不做，正文一个字不动。刷新、重新看一遍影响，再决定怎么改。

### 时间线：这本书做过什么，一条线看完

哪一章拍了什么板、登记了哪段正文、什么时候回退过、哪次体检没过、哪些章节被标了待复核——这些事以前散在聊天记录里。现在它们按时间排成一条线。

点回退条目能看旧线；可以只看拍板、只看回退、只看体检。时间线是回看用的，不会改你的账本。

### 章末体检：写完一章，先看有没有漏

一章写完，切到「体检」。它会按这一章列 10 项检查：还有没有没答的决策、拍了板有没有登记正文、有没有等你确认的设定、有没有该续写检查的段落、正文有没有跑偏、有没有没登记的区间、有没有到期没处理的承诺、哪些章节被标了待复核、旧账有没有缺正文位置……

结果分「阻断 / 提醒 / 提示」。它只把问题摆出来，不替你改稿，也不会自动把问题标成已解决。

找不到正文时它会直说，并跳过跟正文有关的检查——那不叫「检查通过」。

### 搜索：找回一句设定背后的决定

想找「药园里的灵草后来定归谁了」，或者某个人物什么时候知道秘密，不用翻几十章聊天记录。在地图页搜索人物、秘密、物品或关键词，能找回当时的决定、设定和承诺。

搜索的是这本书的剧情账本，不是正文全文。

### 换方向之后，让 AI 知道新方向

回退或改选之后点「继续写」，拍板不会只丢给 AI 一句「接着写」。它会整理一张重写工单：这次改了什么、新方向必须发生什么、哪些旧事不能再出现、哪些设定还要记得、从上一段的哪句话后面接。

工单会交回当前会话；没有可用的续写入口时，可以复制工单手动发。正文还是你和 AI 写，工单只负责把新方向说清楚。

### 朱批纸本：右栏终于像一本稿纸

右栏换成了暖纸、墨字、朱砂的纸本风格：朱砂标当前和风险，青玉表示已经落账或检查通过，琥珀提醒还有事没处理。地图、时间线、体检三个视图各看一件事，浅色和深色都跟着 DSH 走。

| 视图 | 你想知道的事 |
|---|---|
| **地图** | 这本书定了什么？哪一章还有岔路没回答？ |
| **时间线** | 什么时候拍过板、登记过正文、退过旧线？ |
| **体检** | 这一章还有哪些决定、段落或承诺需要处理？ |

搜索就在地图页。找一条旧决定、回看一次回退、检查当前章，不必再从整段聊天记录里翻起。

## 上一版能力：v0.8 的右栏拍板台，继续保留

- **按章看决策**：展开章节，查看当前选择、其他走向和对应的设定变化。
- **回退前看影响**：确认前列出将截断的正文字数、作废的段落、撤回的设定和重开的后续决策。
- **回退与改选**：确认后回退，或选择另一条走向重新落账。
- **旧线留档**：侧栏回退默认先保存正文与账本快照，之后可以只读查看旧线。
- **后续章节待复核**：可以把后续章节标记为待复核，提醒自己检查人物动机、关系与因果；标记本身不改正文。

这些能力在 0.9 里继续可用，也接上了时间线、体检和重写工单。

## 快速开始

不用改变原来的写作方式，也不用一直开着。

### 1. 安装 v0.9.1

需要 DeepSeek Harness。插件可以独立安装，不要求同时安装其他小说插件。

**从 npm 安装 0.9.1：**

```bash
dsh plugin --profile web add dsh-novel-beat@0.9.1
```

**或从 GitHub 固定到 v0.9.1 标签：**

```bash
dsh plugin --profile web add "github:DrizzleGig/dsh-novel-beat#v0.9.1"
```

这里的 `web` 是示例 profile 名，请换成你实际使用的 profile；桌面端若使用 `desktop`，就将 `web` 改为 `desktop`。装好后重启 Harness。

> 不带版本号的 npm 命令会安装当时的 latest；GitHub `main` 与本地源码是开发版，都不等同于固定的 `v0.9.1` 标签。

### 2. 开启拍板

默认关闭。在要处理重要剧情的章节开始前，输入：

```text
/beat on
```

也可以点输入框旁的「拍板」按钮。默认保护的正文目录是 `正文`；如果你的正文放在其他目录，先用 `/beat body 路径` 添加。

### 3. 在岔路口做决定

像平常一样告诉 AI 写第几章、往下写。遇到关键剧情节点时，拍板给出 2–4 个有区别的走向及其代价。你确认方向，AI 接着写这一段，登记正文，再做结构核对。

第一次使用，可以从涉及秘密、人物关系或重要物品的一场戏开始。

### 4. 打开右栏「拍板台」

在右侧插件栏打开「拍板台」：地图看决定，时间线看历史，体检看本章待办。写到一半改变主意时，先查看影响预览，再确认回退或改选。

关闭拍板后，右栏仍可查看历史，但不能在侧栏执行回退或改选。

## 一个写作场景

你让 AI 继续写秘境夺宝：主角发现一株即将成熟的灵草，泥土里却还残留着禁制。有人先来过，而灵药成熟后又会引来附近的修士。

拍板把岔路交给你：

- **先探禁制，再谋灵药**：多花时间与符箓，换取对风险的了解。
- **布下后手，伺机取药**：争取机缘，也可能与禁制的主人结下因果。
- **暂避锋芒，记下位置**：保住底牌，接受灵药可能被别人拿走。
- **借他人之手，坐观其变**：借势探路，也承担暴露行踪的风险。

你选择暂避。正文从留下标记、隐匿气息接着写；确认并落账后，「主角没有取药」「禁制仍在」就成了下一章需要遵守的事实。

后来你想改成「先探禁制」。在地图里找到这条决定，先看回退会影响哪些正文、段落和设定，保留快照，再确认改选。后续章节可以标成待复核；新的重写工单交回会话，AI 从新的方向继续。

**决定由你下，AI 负责把代价写出来。**

## 日常怎么用

拍板记两类重要信息：**已经确定的事实**（比如「灵草还在药园」），以及**答应过、还没兑现的事**（比如「禁制的主人迟早会查来」）。开新章前看一遍，写完后再核对，帮助你维护长篇的连续性。

| 你说的话 | 拍板能帮你处理什么 |
|---|---|
| 这个秘密暂时不能让所有人知道。 | 把知情范围的变化列为需要确认的剧情决定。 |
| 这两个人到底要不要合作？ | 展开不同关系走向及其代价。 |
| 上一章答应的事，这章该兑现了吗？ | 检查答应过、还没兑现的事。 |
| 下一章之前，看看之前定过什么。 | 汇总已经确定的事和还没处理的事。 |
| 这章写完了，看看还有哪里没落账。 | 结合段落登记、核对和章末体检检查遗漏。 |

### 作者侧命令

| 命令 | 作用 |
|---|---|
| `/beat on` / `/beat off` | 开关拍板模式；关闭后撤下拍板的工具和提醒，侧栏保留历史查看。 |
| `/beat status` | 查看开关状态、受保护的正文目录，以及当前章还有哪些决定没处理。 |
| `/beat body <路径>` | 添加一个受保护的正文目录，默认目录为 `正文`。 |
| `/beat body reset` | 将受保护的正文目录恢复为默认的 `正文`。 |
| `/beat list [章]` | 列出本章或指定章已经登记的段落、字数，以及关联的决定。 |
| `/beat revert [段号]` | 回退指定段落和它后面的段落；不传段号时处理当前章最后一段。段号可以从段落列表里看。 |
| `/beat fork <要决定什么>` | 主动插一条岔路，让模型先把它整理成决定点再问你。 |

回退会改正文。平时改选建议从右栏进入，先看影响再确认。命令回退另有 `!` 重新定位选项，适合正文已经改过、但你确认要按登记时的原文重新定位的情况；只有能唯一定位时才继续，找不到或出现多处仍会拒绝。使用前先备份并核对目标。

开启拍板后，输入框上方还有一条段落状态栏，可以查看当前章、已登记段落和最后一段字数，并使用「重写这一段」「刷新」。它与右栏拍板台可以同时使用。

## 适合谁，以及它的边界

适合用 AI 辅助写作、又想自己掌握关键剧情的作者；也适合人物多、关系复杂、伏笔多的长篇连载。故事简单、只想直接生成一段正文时，不必为了使用插件而增加流程。

- **正文由你和 AI 写。** 拍板不接管正文生成；作者确认的回退会截断受影响正文，这与生成新正文是两回事。
- **关键选择由作者确认。** 模型的猜测不能直接当成已确认设定，还没答的决定仍要在对话里完成；侧栏改选用于调整已有选择。
- **体检关注结构。** 它不评价文笔、文学水平或人物是否鲜活，也不保证找出所有错误。
- **改选后仍需检查后文。** 待复核标记和重写工单提供依据，不会自动改好所有后续章节。
- **旧线用于查看。** 本版不提供一键撤销回退、自动恢复整本书或多条剧情路线随意切换。
- **本版不提供多书切换面板、决策依赖图、批量拍板或决策地图导出。**

## 数据与安全

账本保存在本地工作区：

```text
<工作区>/.dsh-novel-beat/<书名>/
├── book.json     # 剧情决策账本（含历史记录）
└── rewinds/      # 侧栏回退时保存的正文与账本快照
```

账本格式与 v0.7 / v0.8 兼容；从 v0.6 升上来的旧账会在第一次打开时自动整理。

- **本地保存**：账本与快照留在工作区。插件自身不主动上传正文；写作会话中的模型请求仍由 DSH 和你配置的模型服务处理。
- **默认留快照**：侧栏回退默认保存正文与账本快照；可以取消勾选，但建议保留。关闭快照后，不能指望这次回退仍有旧线可查。
- **先核对再回退**：右栏会检查这段正文还在不在、内容有没有被改过。旧账如果没有记下正文位置，或者正文已经变化，可能只能查看，不能直接安全回退。
- **只读查看不等于恢复**：旧线供查阅与找回文字参考，不会自动覆盖当前正文或账本。
- **备份整个项目**：升级或大规模调整剧情前，建议同时备份正文和 `.dsh-novel-beat` 目录，保留账本与相关快照。

快照给你留下回看旧线的机会，日常备份仍要自己保存。

## 常见问题

### 拍板会自动写小说吗？

不会。它帮助识别剧情岔路、记录选择和核对。正文仍由你与 AI 在写作会话中完成；「继续写」只是把重写工单交回会话。

### v0.9.0 能直接打开 v0.7 / v0.8 的账本吗？

可以，账本格式没有变。旧账里有些决定没有记下正文位置，可以查看，但不一定能直接回退。升级前建议备份正文和账本目录。

### 关闭拍板后，还能看以前的决定吗？

可以。右栏保留历史查看，侧栏回退和改选会禁用。需要继续受控写作时，再用 `/beat on` 开启。

### 我已经写了几十章，还能改以前的决定吗？

能否回退，要看那条决定有没有记下正文位置、正文后来有没有被改过。先在地图里查看影响预览；可以执行时再确认回退或改选，并检查被标记为待复核的后续章节。

### 回退后，原来的正文还能找回来吗？

保留了快照，就可以通过旧线查看回退前的文字。回退会实际截断当前正文，旧线也不是一键恢复按钮；重要修改前请另做备份。

### 为什么提示「看到的是旧版本」？

可能是你打开面板之后，另一边又写了一轮，账本已经更新。这次回退或改选会停下，正文不动；刷新面板，重新看一遍影响再操作。

### 体检没有阻断，就代表这一章完全没问题吗？

不是。体检只核对已经记下的信息，以及它能读到的正文。提醒、待复核、旧账没记下正文位置这些事仍然要处理；如果提示正文读不到，跟正文有关的检查其实没做完。它也不评价文笔与情绪效果。

### 搜索能搜整本正文吗？

不能。当前搜索范围是账本里的决定、设定和承诺。正文全文请使用你自己的编辑器搜索。

### 一定要装别的插件吗？

不用。拍板可以单独用；别的插件想配合，只能读这本书的账本和接收落账通知，改不了你的选择。

测试数字取自本版 [CHANGELOG](./CHANGELOG.md) 的发布检查记录；该记录同时列有 `npm run check` 与 `git diff --check` 通过。

### 工具与集成

11 个工具分别是 `beat_plan`、`beat_next`、`beat_segment`、`beat_revert`、`beat_fork`、`beat_list`、`beat_decide`、`beat_gate`、`beat_compile`、`beat_verify`、`beat_adjust`。参数和调用条件见 [工具文档](./docs/tools.md)。

`novelBeat` 的本版只读集成入口：

| 接口 | 用途 |
|---|---|
| `identity()` | 获取插件身份、版本与服务能力。 |
| `getStatus()` | 获取章节状态与待处理事项。 |
| `getRevision()` | 获取真实账本版本与最近历史记录信息。 |
| `getCanon()` | 获取已确立的事实与义务。 |
| `getArtifact()` | 查询段落或决策等产物凭据。 |
| `onDidCommit()` | 订阅成功提交后的事件。 |

新读取接口不会为读取而写账本；遇到更早的 v1 账本，仅在内存中迁移。历史兼容入口 `query()` / `resolveBook()` 仍可能触发旧账本落盘迁移，新集成应优先使用上述接口。

开发者升级时还需区分：

- `schemaVersion` 是数据格式，`book.revision` 是变更版本，`revisions[]` 是历史记录，三者不能互换。
- `query().version` 保留原来的账本格式含义；插件版本请读取 `identity().version`。
- `beat_segment` 返回的 `revision` 在 v0.9.0 中改为整数账本版本，原快照对象改放在 `revisionRecord`。
- 侧栏回退 / 改选通过 `expectedRevision` 检查版本冲突；不要据此假定所有工具都支持 `expected_revision`。
- 面板「体检」是只读检查，与写作流程里会记录核对状态的 `beat_verify` 不是同一个入口。

更多信息见 [集成契约](./docs/contract.md)、[编排适配说明](./docs/conductor-adapter.md)、[架构说明](./docs/architecture.md) 与 [v0.8 实现说明](./docs/v0.8.0-implementation.md)。
