# dsh-novel-beat｜拍板

**关键剧情由你决定，故事由你掌舵。**

写长篇时，AI 可能替你决定谁知道秘密、人物关系如何变化、下一章走哪条路。「拍板」会在这些关键岔路停下来，列出不同走向及代价；你选定后，它记录决定、供后文核对，也让你回看改动的依据。

它适合想保留剧情决定权、又需要维护长篇连续性的作者。默认关闭；正文仍由你和 AI 在写作会话中完成。

## 当前本地版本：v0.10.2（未发布）

截至 2026-11-25，这是本地实现，不是 npm 发布版；未安装、未接入 kit，也未在真实书上验证。

- 账本使用 `schemaVersion: 3`；旧版账本逐版迁移，迁移前备份 `book.json.bak`，旧证据保留为 legacy，不伪造锚点。
- 新决策须通过状态差分与证据闸门；状态键受白名单限制，选项须说明行动、代价、结果、信息增量、风险和变化。重复差分、无变化、过期证据及没有真实代价的假分叉会被拒绝。
- 没有候选的章节也要登记带理由的扫描收据；相关正文或账本输入变化后须重新扫描，收据有效时才能核对。
- 作者选定后可登记正文；原证据前缀和已登记输出仍须匹配。账本列表和编译结果可回查证据及完整选项；自动核对不代替作者审稿。
- 普通命令与面板回退共用正文/账本成对事务：提交前复核版本与内容，保存快照、原子替换并检查回执；恢复失败会隔离该书并暂停写入。后续章节只标为待复核，不自动改正文。
- 右栏拍板台可查看决定、证据、打断原因和回退影响。voice 只读适配仅用于候选排序；当前 voice 0.2.2 缺少会话启用状态和人物画像接口，因此会降级为基线排序。
- 段落循环仍是本地实验：只有设置 `DSH_NOVEL_BEAT_SEGMENT_LOOP=1` 才额外注册 `beat_append`、`beat_finish`；默认关闭，不代表已发布或可用于真实书。

## 快速开始

开发者可在本地 profile 的 package.json 中用 link: 指向源码目录：

```json
"dsh-novel-beat": "link:D:/path/to/novel-beat"
```

将路径替换为本机仓库目录，并确保此包已加入 profile 的 dsh.profile.bundles，再重启 DSH。v0.10.2 尚未发布，当前不能从 npm 安装此版本。

默认关闭。在要处理重要剧情的会话里输入：

```text
/beat on
```

然后打开右侧插件栏的「拍板台」。正文不在侧栏编写；默认保护的正文目录为 `正文`，需要时可用 `/beat body <路径>` 添加目录。

## 一次拍板怎么用

1. **问**：像平常一样让 AI 继续写；走到关键岔路时，拍板列出不同选择及其代价。
2. **选**：由你确认方向，未确认的提案不会变成已定事实。
3. **写并登记**：在写作会话中完成正文，再登记对应段落；没有岔路的章节也要留下扫描收据。
4. **核对**：检查证据、已登记正文和未完成事项；结果用于提示，不代表文学审稿。
5. **回看或改选**：在右栏查历史与影响；确认回退后，再检查被标为待复核的后续章节。

## 右栏与回退

- 回退预览会绑定账本版本和正文内容；如果期间发生变化，会因版本冲突停下，刷新影响后再操作。
- 普通回退与面板回退使用正文和账本成对事务，默认先保存成对快照，再校验提交结果。
- 回退后后续章节正文不变，只标记为 stale／待复核；重写简报失败可单独重试。
- `rewinds/` 中的旧线供只读查看，不会自动覆盖当前稿件。

## 系列里的其他插件

小说系列提供几种可选的专门能力。它们按需搭配；「拍板」可以独立运行，不要求安装其他系列插件。

| 插件 | 能力 | 什么时候考虑搭配 |
|---|---|---|
| `dsh-novel-kit` 小说工作台 | 将章节计划、拍板、草稿、记忆、文风和原著依据放入一套工作流。 | 想在一个工作台里推进整章、管理草稿与检查时。 |
| `dsh-novel-fade` 褪色 | 保存章节记忆和原文，逐渐淡化旧记忆，并在写前生成简报。 | 连载篇幅很长、希望减少重复携带旧章时。 |
| `dsh-novel-voice` 创作风格 | 从作品建立文风档案，提供写前提示和写后检查，可针对片段调整表达。 | 想参考指定文风，或检查套话、重复表达并定点修改时。 |
| `dsh-novel-fanfic` 同人工作室 | 记录带章节和原文依据的 canon，并区分原著事实与本作设定。 | 写同人、需要回查原著依据或维护 AU 差异时。 |
| `dsh-novel-conductor` 故事总控 | 编排一章的准备、写作、登记、核对、记忆沉淀与收尾步骤。 | 想按 runbook 管理一章流程和步骤收据时。 |

以上介绍只说明各包的角色，不表示它们已与当前本地 beat 版本接通；请按需查看各包自己的说明。

## 边界

- 拍板不会自动生成或改写正文，也不会替作者选择方向；作者确认回退时，正文会按预览截断。
- 它帮助核对结构与记录，不能保证文笔、剧情或事实完全正确，也不能保证找出所有问题。
- 锁只覆盖当前进程；同一本书不要让多个写入流程同时操作。
- 旧线可供查阅，不是一键撤销或自动恢复整本书的功能。

## 数据与安全

- 账本位于工作区的 `.dsh-novel-beat/<书名>/book.json`；回退快照保存在同一书目录的 `rewinds/`。
- 迁移及回退会保留账本／正文备份与快照；升级或大幅改剧情前，建议另行备份整个项目。
- 插件本身不主动上传正文；写作会话中的模型请求仍由 DSH 和你配置的模型服务处理。

## 常见问题

### 拍板会自动写小说吗？
不会。它提出候选、记录选择并核对；正文由你和 AI 在会话中完成。经你确认的回退会修改正文。

### 可以修改早期决定吗？
可以先在右栏查看影响，再确认回退或改选。能否安全执行取决于账本是否有正文位置记录、正文是否仍匹配。

### 回退后能找回原文吗？
保留了快照时，可以在旧线里查看回退前内容；旧线不会自动恢复到当前正文。重要修改前仍应自行备份。

### 关闭拍板后还能看历史吗？
可以查看右栏历史；关闭后不能在侧栏执行回退或改选。再次开启可用 `/beat on`。

### 必须安装其他系列插件吗？
不需要。「拍板」可以单独运行；其他插件均为可选搭配。
