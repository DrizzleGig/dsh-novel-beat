# dsh-novel-beat v0.7.0 实测问题评审稿（第 11 章，2026-11-15）

给评审者：这是一次真实会话的实录。插件 = 拍板（novel-beat），它把"剧情岔路"登记成账本里的决策点，
由插件自己在卡片里问作者，作者答完落账，然后模型接着写。下面只列**真实发生的**现象与我的判断，
最后有三个问题想听你的意见。

## 二、我判断的三个问题

### 问题 1：`beat_next` 因为「没被选中的那个选项」冲突，拒绝提问

`beat_plan` 阶段给出的是**两个备选走向**：A「雪珂引荐」，B「侯府投帖」。
B 与全书 canon（陈凡对东宫的态度 = 装傻）冲突，这本来**正常**——作者可能正想选 A，B 摆出来只是对比。

但 `beat_next` 在**提问之前**就把「任一选项与 canon 冲突」当成致命错误，直接拒绝发问：

```
决策点 b11-1 选「侯府投帖：以龙骧侯独子的身份自己上门」与全书 canon 冲突
```

模型只好把这一条决策整个作废、改名、重来——多花两轮，作者一次都没被问到。

**我的判断**：冲突应该在"作者选了它之后"才拦，或者只作为预览警告（选 A 就没事）。
提问前拦死等于"因为有个我不选的选项不行，所以这个问题不能问"。

### 问题 2：节奏还是塌了——一章一个决策、整章一次写完、整段一个 segment

设计目标是：**写一段 → 遇到岔路 → 问一次 → 按答案接着写这一段 → 登记这一段 → 再问下一个**。

实际是：
- 第 11 章从头到尾只有 **1 个决策点**；
- 模型**一次性写完**整章（2391 字，Created file），中间没问第二次；
- 写完才 `beat_segment`，把 **0–2391 整章登记成一个段落**，正好满足 `segment-required`（上一条已登记），于是节奏闸形同虚设。

`segment-required` 只要求"上一条决策有段落"，模型把"整章"当一个段落交上来就过关了。
所以**"写一段问一个"实际变成"写一章问一个"**。

### 问题 3：`reset:true` 的语义自相矛盾

`beat_plan(reset:true)` 的说明是"清空本章未拍板决策点后重排"，但实际报错
「本章已有同名决策点：陈凡怎么进月轩」——它按标题去重，于是"重排同一条"永远失败，只能改名。

## 三、想听你的意见（请逐条判断，别客套）

1. **问题 1 该怎么改**：提问前只做预览、不拦；还是有别的更稳的做法（比如把冲突选项标记成"会改设定"交给作者确认）？
2. **问题 2 才是根**：在不设硬配额、不诱导造假岔路的前提下，怎么让"一章多个段落"真的发生？
   我列了几个候选，请你判断哪个可行、有没有更简单的：
   - A. 段落字数上限（如单段 ≤800 字）：`beat_segment` 拒绝超过上限的区间，逼模型分段写；
   - B. 写入闸：已登记段落末尾之后，一次 `write` 的新增正文超过 N 字就拒（`beat_segment` 先登记再写下一段）；
   - C. 只在技能/系统提示里强调，不做代码闸（我怀疑没用，因为这次模型就是主动整章写完）；
   - D. 别的办法。
   我担心 A/B 都会诱发"为凑段落硬切"或"造个假岔路解锁"，你之前也警告过这类副作用。
3. **问题 3**：`reset` 应该按标题去重，还是"重置本章所有未拍板决策、允许同名重建"？哪个更符合作者直觉？

## 四、已知的边界（不用再提）

- 插件拦不住 `pwsh` 重定向、第三方写盘；只拦 `write`/`edit`/`apply_patch`/`str_replace_editor` 对正文目录的写。
- 卡顿、模型推理质量不在插件控制范围。
- 回退（`beat_revert`）现在已经改成"hash 不对先重定位、定位不到就拒绝"，不再硬截。
- 作者可以 `/beat fork` 自己插岔路，模型必须先用 `beat_plan(forkId)` 消化它。
