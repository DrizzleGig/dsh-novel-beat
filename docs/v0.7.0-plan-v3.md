## 三、"每章 3 个决策点"的根因（回答第 4 问）

代码里没有 3：`beat_plan` 允许 1–20 条，全仓只有两处 "2–3" 是注释与技能里的反面提醒。
真实账本 `D:\斗罗大陆\.dsh-novel-beat\斗罗：开局炸毁冰火两仪眼\book.json` 的分布是：

```
第1章: 5 条   第2章: 3 条   第3章: 3 条   第4章: 4 条   第5章: 3 条
第6章: 3 条   第7章: 3 条   第8章: 3 条   第9章: 3 条   第10章: 3 条
```

而且第 2–10 章的第三条几乎都是「第 N 章最后落在哪个钩子 / 章末钩子」。
这不是岔路密度，是**章级模板**：开局一个、中段一个、章末钩子一个。
模型按章批量规划时，会把"钩子"当成第三条决策点填满，于是每章恰好 3 条。

所以修法不是写一个"岔路检测算法"，而是**掐掉按章批量规划的入口**：

- `beat_plan` 一次只收 1 条（多给报 `one-at-a-time`）；
- 技能文案改成"写到那个岔路才登记，不预先规划整章"；
- 岔路该不该有，是模型读正文时的判断，插件不做文本级检测（评审一致认为做不到，且硬做会教模型造假岔路）。

## 四、为什么不给"本章必须问过至少一个岔路"设硬门槛

工程评审给出了两条真实死锁，任一条都会让工具不可用：

1. **登记死锁**：作者要求"先写一段过渡"，此时本章没有"已拍板且未占用"的决策 →
   `beat_segment` 空决策被拒、挂旧决策是 `already-segmented`、挂新决策是 `not-committed`。
   模型只能造假岔路或绕过登记。
2. **答案死锁**（今天就能复现）：作者在卡片里自己写答案 → 决策停在 `answered`；
   `beat_decide` 又被 `use-beat-next` 拒掉 → 永远到不了 `committed` → 第 2 段起全部登记不上。

所以：

- **不设**"第 2 段起必须带决策"的硬门槛；
- 作者自定义答案的死锁**已修**：`answered` 状态允许 `beat_decide` 补齐 changes 落账；
- 岔路过少的信号交给 `beat_verify` 的 warning（`unsegmented:` / 决策数低于本书前几章基线），不在写正文时弹错。

## 五、本轮已实现（112 测试全绿）

| 项 | 做法 | 证据 |
|---|---|---|
| A 单条规划 | `beat_plan` 多给报 `one-at-a-time`；schema `maxItems:1` | `test/next.test.mjs` |
| B 正文可见 | `beat_segment` 返回 `text`（≤600 字预览 + 总字数），卡片直接显示这一段 | `test/segment.test.mjs` |
| D 安全回退 | 退第 N 段 = 截断到它的 `offsetStart`，**N 及其后所有已登记段一起作废**；canon/义务按倒序还原；一条 `revision(kind=revert)` 记 `revertedSegments`；返回"从第 X 字重写"的话 | `test/segment.test.mjs`（级联用例） |
| D 入口 | `/beat list [章]` 列本章段落；`/beat revert [段号]`（不传=最后一段） | `index.js` 命令 |
| F 卡片去重 | `detail` 只写"这会改变：…"，选项只走 `options` | `test/next.test.mjs`（detail 不得含选项 label） |
| 证据归一化 | `lib/verify.js` 匹配前做 NFKC + 去空白/零宽/标点/markdown 标记 + 小写 | `test/verify.test.mjs` |
| 死锁修复 | `answered` 状态下允许 `beat_decide` 补 changes | `test/next.test.mjs` |

回退语义（评审后确定）：快照只用来做审计与将来恢复，**正文的唯一真相是章节文件**；
回退不靠快照重建文件，而是"截断 + 级联作废"，因此前缀段落的 offset/hash 始终有效，
`beat_verify` 不会因为回退而产生假漂移。
