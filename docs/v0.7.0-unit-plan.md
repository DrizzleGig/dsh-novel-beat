# v0.7.0 写作单元闸（第 7 条回归）设计 v1
## 一、要堵的是什么

实测（第 11 章）与模拟第 13 步都出现同一件事：**模型一次 `write` 把整章写完，再补一个 `beat_segment`
把整章登记成"一段"**。正文在作者拍板之前就存在了，节奏闸（一次一个岔路）形同虚设。

现在 `write` 是整文件覆盖，guard 只看账本状态（有没有未问的岔路 / 要不要续写检查 / 有没有待确认的选项），
看不出"这一次写的是这一段还是整章"；`beat_segment` 事后登记也无从判断。

## 二、不做什么

- **不加字数配额**：ChatGPT 与两轮评审都指出，按字数卡会让模型造"假岔路"来解锁，污染 canon。
- **不新增工具**：不让模型多学一个命令，闭环仍是 `beat_plan → beat_next → write → beat_segment → beat_verify`。
- **不禁止整文件写入**：`write` 仍是唯一写正文的方式，改错字、修排版都还要能用。

## 三、核心概念：写作单元（unit）

> 写作单元 = 上一次 `beat_segment` 的终点（锚点）之后，这一次 `beat_segment` 登记的文字。

一个单元对应一个已拍板的决策（或一次续写检查判定"这里没有真岔路"）。作者拍板在前，单元正文在后，
这是节奏闸唯一要求的结构顺序。

## 四、三条不变式

### A. 提问前不许有未登记的正文（挡"先写完再问"）

`beat_next` / `beat_plan` 走"要作者拍板"的路径时，读一次本章正文文件：

- 若本章已有登记段落：`正文长度 − 最后一段的 offsetEnd`（去掉尾部空白）必须为 0；
- 否则 → 拒 `write-ahead`：「这一章有 N 字正文还没登记成段落。先把上一段用 `beat_segment` 登记，
  或者把多写的部分删掉，再问下一个岔路。」

这样"先把整章写完、再回头问我"这种顺序被直接挡住。

### B. 登记前不许改写已批准的文字（挡"回填"）

拍板时给账本记一个闸门：

```json
"chapters": { "12": { "gate": { "file": "正文/第12章.md", "offset": 1200,
  "prefixHash": "sha256(正文前 1200 字)", "decisionId": "b12-3", "at": "..." } } }
```

`beat_segment` 登记时核对：

1. `gate.offset` 必须等于本段起点（沿用 `segmentEndFor`，已经保证接续）；
2. `sha256(正文.slice(0, gate.offset))` 必须等于 `gate.prefixHash` —— 已批准的正文没被悄悄重写。

不通过 → 拒 `prefix-rewritten`：「第 N 字之前已登记的正文被改过。要么 `/beat revert` 回到改动处重写，
要么把改动撤回去再登记。」

### C. 单元必须写在决策之后（挡"拍板前先写这一段"）

`gate` 本身就是这道证明：它记的是"拍板那一刻正文长度"。`beat_segment` 要求本段起点等于 `gate.offset`，
于是这一段只能是拍板之后新写的字。配合 A（拍板前不许有多余正文），这两条把
"先写后问 / 先问后写"的顺序固定下来。

## 五、粒度问题怎么办（不设配额）

结构上挡得住"提前写"，挡不住"一个单元写得很长"。这不该用硬配额解决，而是：

- `beat_segment` 记录 `unitChars`（本单元字数），卡片与返回值里显示；
- `beat_verify` 增加诊断（不阻断）：
  - `coarse-unit:<segmentId>: 这一段 N 字，占本章 M%——一章只问一两个岔路时，作者会觉得自己被跳过了`；
  - `thin-forks: 本章 K 段里 J 段没有决策点`；
- 诊断只进 warnings，不影响 `pass`，作者自己决定要不要拆。

## 七、已知边界（写进 README）

- 只认 `write` / `edit` / `apply_patch` 落在受保护目录里的正文；`bash` 重定向、外部编辑器写盘看不见。
- 手工改正文不会被强制打断，但 `beat_segment` / `beat_verify` 会报 `prefix-rewritten` / `drift:`，需要作者处理。
- "这个单元里其实藏着没被问的岔路"属于内容判断，插件不做文本级检测，只能靠 `beat_verify` 的诊断与作者自己的眼力。

## 八、实现状态（v2，已落盘并测通）

ChatGPT 这轮评审指出 v1 有四个洞，逐条改法如下（都已实现）：

| 洞 | v1 的问题 | v2 的做法 |
|---|---|---|
| ① 闸 A 只在两个工具里查，模型可以换入口 | 统一到"产生新决策 / 提问"的所有入口：`executeNext`（提问、确认提交）与 `executePlan`（登记新决策，含 reset）都先过 `unitInspect` | 两处都 `fail('write-ahead')` |
| ② 闸 B 只绑前缀 hash | 闸门还绑 `file` 与 `decisionIds`；闸门**只能由拍板创建**，且登记成功即 `consumed: true` | `unit-gap` / `prefix-rewritten` / `gate-mismatch` 三个码 |
| ③ 闸 C 只是逻辑推导 | `beat_segment` 必须消费唯一一道未消费闸门，成功后原子更新段落与闸门状态；`segment` 记 `unitChars` | 闸门 `consumed` + `consumedBy` |
| ④ 工具之外的写入看不见 | 不假装能管；写进 README 与这里：这是**工具面内的协议**，不是沙箱 | 边界声明 |
