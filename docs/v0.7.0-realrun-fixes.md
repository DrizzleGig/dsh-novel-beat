# v0.7.0 实测三问的修复（2026-11-15）

依据：第 11 章实测实录（`docs/v0.7.0-realrun-review.md`）+ 作者 ChatGPT 的两轮意见
（`docs/v0.7.0-realrun-review-result.md`）。三条都按"最小可用、不新增工具"实现，
测试从 117 例增到 **119 例全绿**。

## 一、冲突选项不再硬失败：可恢复的提交（问题 1，P0）

以前：作者选的选项和 canon 对不上 → `beat_next` 直接 `canon-conflict` 报错，选择作废、
整条决策只能 `beat_plan(reset)` 重来。作者白回答一次。

现在是一条可恢复的路径，**不增加新工具、不改变工具链**：

```
beat_next            作者选 B（会改 canon）
  ├─ 无冲突 → 正常 commit（凭据 origin=author）
  └─ 有冲突 → 存成 pendingChoice（status=answered）+ audit conflict-pending
              → 返回 needsCanonConfirm + message（让模型去问作者"能不能改设定"）
beat_next(confirmCanon: true)  作者同意 → 覆盖 canon，留 canon-overridden 痕迹
```

- canon 被覆盖时，条目上记 `overridden: true`，并且返回 `canon-overridden:实体.键:旧→新` 警告；
  audit 里对应那条 `commit` 带 `canonOverride: true`。
- 没确认之前**不写凭据**、canon 不动——账本不会出现"改了设定但没提交"的半截状态。
- 作者拒绝就 `beat_plan(reset:true)` 重给选项，不用重新问已经答过的那些。

涉及：`lib/schema.js`（`applyChangesToCanon` 增加 `override`）、
`lib/tools.js`（抽出 `commitAnswers()`，`executeNext` 增加 `confirmCanon` 分支与
`pendingChoice` 早返回）。

## 二、续写检查：一段写完，先回答"后面还有没有真岔路"（问题 2，P0）

ChatGPT 给的最小版本，只加一个标记，不用状态机、不设段落字数配额：

- `beat_segment` 成功 → `chapters[N].continuationCheckRequired = true`；
- guard 对"第 N 章"的写盘：标记为真 → 拒 `[CONTINUATION_CHECK]`，要求在写下一段前先做一次检查；
- `beat_plan` 有结论 → 清标记（写 audit `continuation-check`）：
  - 有真岔路：正常登记这一个（`verdict: fork`）；
  - 确实没有：`beat_plan(beats: [], reason: '…')`（`verdict: no-fork`），**不造假决策**；
- `beats` 为空是合法调用（schema 的 `normalizePlanBeats` 允许空数组），`reason` 少于 2 个字 → `no-reason`。

边界（写清楚，别假装能保证）：模型可以撒谎说"没有岔路"。代码只保证"必须回答一次"，
回答得对不对只能靠真实写作 + `beat_verify` 的 `unsegmented:` 提示回头看。

## 三、reset 的执行顺序与 ID 分配（问题 3，P1）

以前：先查"同名决策点"，再判 reset → `reset:true` 同名重建永远失败（第 11 章卡了两轮）。

现在：

1. `reset` 先执行：清掉本章**未拍板**的决策（并把它们占用的 fork 放回 `open`），
   已拍板的决策和它们写进 canon 的结果**保留**；
2. 再查重名：`reset` 时不和已拍板的旧同名决策冲突（允许重建同一条岔路）；
3. 新决策**分配新 ID**：`book.json` 增加 `counters.decisions.<章号>` 高水位，
   `nextDecisionId(decisions, chapter, floor)` 取 `max(现有最大号, 高水位) + 1`，
   所以 reset 删掉的号不会被复用（历史 audit / 段落引用不会指错）。

## 五、模拟测试（14 步，13 通过）

模拟脚本：`D:\插件\tmp\beat-v07-spike\sim-rhythm.mjs`——按"模型会怎么走"编排 14 步，跑**真工具 + 真 guard**

结论：13/14 通过——开场可写、有岔路没问拦住、拍板后放行、登记一段后要续写检查、
`beats: []` 声明无岔路可放行、选到会改设定的选项先待确认（canon 不动、不许写）、
确认后提交并留 `canon-overridden`、reset 可同名重建。

guard 看不出这一次写的是"一段"还是"整章"。
