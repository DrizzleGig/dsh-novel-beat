## 二、诊断（代码 / 账本证据）

**P1**：正文由模型 `write` 直接写文件，`beat_segment` 只做事后测量（`lib/tools.js:1461-1486` 入参只有 `file` + `decisionIds` + 可选定位），**不接收正文**，所以会话里没有那一段文字。

**P2**：`beat_revert` 已实现，但本轮实测两次写作（第 8 章走 `beat_decide` 旁路、第 9 章 `beat_next(ids:[…])` 后整章 `write`）**都没有调用 `beat_segment`**，账本里没有段落 → 没有可退对象。作者侧也没有入口：`/beat` 只有 `on|off|status|body`。

**P3**：现行 `lib/enforce.js` 的规则是"本章有**没问的**岔路才拦"，0 决策时直接放行 —— 这是我在上一版亲手开的洞。

**P4**：代码里没有"每章 3 个"的常量（`beat_plan` 允许 1–20 条，`lib/tools.js:1434`）。真正的原因是**按章批量**：模型先在章级别排出最大的 3 个关口，一次问掉，然后整章写完。第 9 章实测正是 `beat_plan` 3 条 → `beat_next ids:[b9-1,b9-2,b9-3]`（我当时允许 2–3 个原子组，等于给了批处理许可）。**"3"是"按章规划"的签名，不是岔路密度。** 再加上通用模型"少问、只问关键几个"的训练先验，就把 3 固化了。

**P5**：`lib/tools.js:542-549`，`detail` 里列了一遍 `· 选项：影响`，`options` 又渲染一遍。

## 三、方案（v2）

一句话：**不动"谁能写正文"，改"一次能规划多少、一段必须带什么、退的那一刻退到哪"**，并把可见性交给工具卡片的回显。

### 3.1 P4 先做：`beat_plan` 回到"一次一个岔路"

- `beat_plan` 的 `beats` 只接受 **1 条**；传 2 条以上 → 拒 `one-at-a-time`（"一次登记一个岔路；强耦合的少数情况写成一个决策点、选项里表达组合"）。
- 描述改成："只登记**你刚遇到的那个**岔路。不要提前把整章摆完。"
- 技能文案删掉"密度预期"这类数字（见 §四 为什么不写 5–20），改成："模型自己判断岔路，但必须一次一个；每写一段、每遇一个岔路，就登记 + 问一次。"

理由：这是 1/2/3/4 的共同根因——**模型按"章"规划、插件按"段"处理**。先把工具契约改成按岔路触发，模型就没有"一次问完"的入口。

### 3.2 P1：可见性靠"回显"，不靠模型复述

- `beat_segment` 成功后，输出卡片**回显这一段的正文**（默认前 300 字 + 字数 + 段号 + hash 前 8 位；`full:true` 给全文）。作者在会话里直接读到刚写的那段。
- 技能加一句："写正文用 `write`，写完立刻 `beat_segment` 登记；作者会在登记的卡片里看到这一段。"

**不做**"正文先在回复里说一遍，再传 `beat_segment(text)`"：长段落会二次表述走样（作者看到的和落盘的不一样，比看不见更糟），token 成本翻倍，而且卡片回显已经解决了可见性。

### 3.3 P3：从第 2 段起，段落必须带决策点

| 段落 | 规则 |
|---|---|
| 本章第 1 段（开场） | `decisionIds` 可为空（作者要先看到内容） |
| 本章第 2 段起 | `decisionIds` **不能为空** → 否则拒 `decision-required`："这一段没有任何决策点。一章从第二个场景起就不可能还没岔路——要么补登记岔路，要么把它并回上一段。" |
| 任何段 | 引用的决策必须已拍板、且没被前面的段占用（已有 `already-segmented`） |

这条不需要"字数阈值"这种魔法数字：它把"写一段 → 遇岔路 → 问 → 再写"变成**结构上的唯一通路**。整章一口气写完 = 只有一段 = 后续没有段落可登记，`beat_verify` 会报 `unsegmented`（已有），并且第 2 段一登记就被这条规则挡住。

**例外**：真正的过渡/纯氛围段，允许 `/beat transition <理由>` 在本章**放行一次**（记 audit），避免作者被"必须硬造岔路"绑架。

### 3.4 P2：回退做成"退到第 N 段之前 + 重写这一段"

- 新增命令 `/beat revert [N]`：默认退本章最后一段，可指定段号；`mode` 默认 `both`（正文恢复快照 + 账本撤 canon/义务）。
- 支持**非末段**：退第 3 段时，第 4 段以后整体作废（要求 `force` 或在命令里确认），并给出清单。
- 每次回退写一条 `revision(kind:'revert')`，正文按快照恢复，**不截断**——避免 offset 漂移。
- 命令的返回值就是一条会话消息："第 N 段已作废（正文已恢复到写它之前，canon 撤回 X 条）。请重写这一段，写完用 `beat_segment` 重新登记。" → 模型下一轮就以这条为准重写，作者能直接看到"退掉 + 重写"的闭环。
- 新增命令 `/beat list`：列本章段落（段号 / 字数 / 挂在哪些决策 / hash 前 8 位 / 是否漂移），让作者知道"可退什么"。

### 3.5 P4 的"检测机制"讲清楚（写进 README）

- **谁检测**：模型判断（这属于内容理解，插件不做文本级检测——另起模型调用成本高、误报会训练作者忽略提示）。
- **插件校验什么**（防"编造岔路"）：
  1. `beat_plan` 每条决策必须给 `changes`（entity/key/from/to/**evidence**），不同选项的 changes 必须不同（已有）；
  2. **新增：`evidence` 必须是这一段（或本章）正文里的原句子串**，插件机械校验 —— 编造者必须指着一句真实存在的话说"这里是岔路"，作者一眼能判断指得对不对；
  3. 同一 entity/key 的重复决策会被 `canon` 冲突检查挡住（已有）。
- **密度**：不写固定数字。`beat_verify` 改为**用这本书自己的历史做基线**：若本章决策数低于全书已拍板章节中位数的一半，给一条提示 `thin:第 N 章只有 M 个决策点（前面几章中位数 X），复查有没有漏`。这是提示，不阻断。

### 3.6 P5：卡片去重

`detail` 只保留 `这会改变：…`；选项只出现在 `options`。测试断言 `detail` 不含任何选项 label。

### 3.7 诚实边界（README 必写）

`tools.guard` 只拦结构化写盘工具（`write/edit/apply_patch/str_replace_editor`）；`pwsh`/shell 重定向、第三方进程写盘绕得过去。所以 v0.7 的"强制"应表述为：**拦住结构化写入 + 事后 hash/段落核验**，不是"绝对写不进去"。这条不改代码，改文案——免得作者和后续维护者高估可靠性。

## 四、v1 方案被推翻的四点（红队复核）

1. **"正文一律走 `beat_segment(text)` + 禁写正文目录"** → 否决。理由：①它把插件从"管决策"变成"管全部正文的提交渠道"，违背冻结原则"Beat 不控制全部写作"；②只按工具名拦，模型换个通道就过；③`/beat free` 逃生口会被模型说服作者关掉；④"回复里说一遍 + 再传一遍"必然走样。
2. **开场上限 800 字** → 否决。岔路是事件属性不是字数属性；阈值会让模型在 800 附近**造一个假岔路**来解锁（假决策污染 canon，比漏问更糟）。
3. **"一章 5–20 个岔路"写进文案** → 否决。指令跟随模型会锚定到 5 然后停，还会诱导拆分凑数。改成"一次一个 + 段落必须带决策"的结构约束。
4. **靠 `beat_adjust` 改错字** → 撤销。现行 `beat_adjust` 只做 `waive`/`supersede`（`lib/tools.js` `executeAdjust`），**根本不碰文件**；技能里"错字走 beat_adjust"是错的，一并改正为"错字直接 `edit`；若改在已登记段落内，`beat_verify` 会报 drift，重新 `beat_segment` 登记"。
