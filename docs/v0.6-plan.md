## 0. 一句话目标

0.6.0 把「拍板」从**一段提示词**升级为**一本可查询、可校验、跨章生效的账本**：

- 不装 novel-forge 也能跑完整闭环；
- 作者拍板后写入全书 canon，下一章规划/写作时自动带出；
- 正文写完能校验「该发生的是否发生、不该出现的是否出现、到期的义务是否回应」；
- 对话栏有一个会话级开关，关掉后该会话看不到 beat_* 工具。

## 2. 非目标（0.6.0 明确不做）

- **不接管正文写作**：插件不生成章节、不管理 `chapters/` 目录；`beat_verify` 接收 `text` 或 `path`。
- **不做 AI 语义审稿**：只做确定性校验（证据短语、禁项、canon 冲突、义务到期）。语义是否真的改变，由作者判断。
- **不做侧边栏**：`sidebar.panellist` 的书面板放 0.7。
- **不做多书并发/多进程锁**：单进程内 per-book 串行队列即可。
- **不改 novel-forge**：`format:'novel-forge'` 只是可选导出，不读取 forge 的数据。
- **不保留 0.5 的 `chNNN.json` 作为主存储**：只做一次性迁移。

## 3. 架构

### 3.1 两半

| 半边 | 文件 | 职责 |
|---|---|---|
| Host | `index.js` + `lib/*.js` | 7 个工具、`/beat` 命令、账本读写、compile/verify、会话模式、agent 工具隐藏 |
| Client | `client.js` | `conversation.input.left` 的「拍板」按钮，调 host 的同一个命令 |
| 数据 | `<dir>/.dsh-novel-beat/<book>/book.json` | 单文件账本；原子写 |

### 3.2 为什么是单文件

`decisions` / `canon` / `obligations` 必须一致：一次拍板同时改三样。拆三个文件会出现「decisions 写了、canon 没写」的半状态。单文件 + 原子替换最简单；100 章量级仍是几百 KB。超过 5 MB 再在 0.7 拆。

### 3.3 原子写与并发

- 写：`book.json.tmp` → `rename`（同目录，POSIX/Windows 都原子）。
- 每本书一个 `Map<bookPath, Promise>` 队列；读-改-写在队列任务内完成。
- 读：`JSON.parse` 失败时保留原文件，报 `book-corrupt`，不自动覆盖。
- 备份：每次成功写前，把旧文件复制为 `book.json.bak`（只保留一份）。

### 3.4 路径安全

- `book` 清洗 `[\\/:*?"<>|]`，并拒绝 `.`、`..`、空、绝对路径、盘符。
- `chapter` 必须是正整数。
- `beat_verify(path)`：`path.resolve(dir, p)` 后 `realpath`，必须仍在 `dir` 内；只读 `.md`/`.txt`，上限 2 MB。
- 所有写路径必须在 `<dir>/.dsh-novel-beat/` 下。

## 4. 数据模型（`book.json` v1）

```json
{
  "schemaVersion": 1,
  "book": "示例书",
  "meta": { "title": "示例书", "genre": "玄幻", "logline": "一句话立意" },
  "createdAt": "2026-11-07T14:00:00.000Z",
  "updatedAt": "2026-11-07T14:00:00.000Z",
  "chapters": {
    "1": { "status": "decided", "decisionIds": ["b1-1", "b1-2"], "verifiedAt": null }
  },
  "decisions": [
    {
      "id": "b1-1",
      "chapter": 1,
      "title": "玉佩怎么到手",
      "kind": "得失",
      "change": "玉佩 从 拍卖品 变成 林砚持有",
      "status": "decided",
      "legacy": false,
      "options": [
        {
          "label": "拍卖会竞价拍下",
          "impact": "花钱得玉，得罪同场出价人，后续被盯上；代价是现银见底。",
          "changes": [
            {
              "entity": "玉佩", "key": "持有者",
              "from": "拍卖行", "to": "林砚",
              "evidence": ["落槌", "玉佩入手"]
            },
            {
              "entity": "林砚", "key": "现银",
              "from": "充足", "to": "见底",
              "evidence": ["钱袋空了", "最后一只银锭"]
            }
          ],
          "obligations": [
            { "text": "同场出价人记恨林砚", "dueChapter": 3, "evidence": ["出价人", "记恨"] }
          ],
          "forbidden": ["白送", "捡漏"]
        }
      ],
      "chosen": {
        "label": "拍卖会竞价拍下",
        "impact": "花钱得玉，得罪同场出价人，后续被盯上；代价是现银见底。",
        "changes": [ "…与所选 option 的 changes 相同，拍板时快照…" ],
        "obligations": [ "…快照…" ],
        "forbidden": [ "…快照…" ]
      },
      "createdAt": "2026-11-07T14:00:00.000Z",
      "decidedAt": "2026-11-07T14:02:00.000Z",
      "supersededBy": null
    }
  ],
  "canon": [
    {
      "entity": "玉佩", "key": "持有者", "value": "林砚",
      "chapter": 1, "decisionId": "b1-1", "updatedAt": "2026-11-07T14:02:00.000Z"
    }
  ],
  "obligations": [
    {
      "id": "ob1",
      "text": "同场出价人记恨林砚",
      "dueChapter": 3,
      "status": "open",
      "sourceDecision": "b1-1",
      "evidence": ["出价人", "记恨"],
      "paidChapter": null,
      "waivedReason": null
    }
  ],
  "audit": [
    {
      "at": "2026-11-07T14:02:00.000Z",
      "action": "decide",
      "chapter": 1,
      "id": "b1-1",
      "detail": "选择：拍卖会竞价拍下；canon 变更 2 条；新增义务 1 条"
    }
  ]
}
```

### 4.1 字段约束

| 字段 | 规则 |
|---|---|
| `id` | 决策 `b{chapter}-{n}`；义务 `ob{n}`；全书唯一 |
| `kind` | 八类：动作/知情/关系/得失/状态/承诺/时序/分叉 |
| `status` | 决策 `pending`/`decided`/`superseded`；义务 `open`/`paid`/`waived` |
| `options` | 2–4 个；label 非空且互不相同；每个 option 必须有非空 `changes` |
| `changes` | `entity`/`key`/`to` 非空；`from` 可选但推荐；`evidence` 1–3 条，每条 2–24 字 |
| `obligations` | `text` 非空；`dueChapter` 可选（正整数，≥ 当前章）；`evidence` 1–3 条 |
| `forbidden` | 0–6 条短语，每条 2–12 字；正文出现即失败 |
| `canon` | `(entity,key)` 唯一；value 由 `chosen.changes` 归并 |
| `audit` | append-only；不删 |

### 4.2 关键不变量

1. `decisions` 里 `status=decided` 的 `chosen.changes` 必须非空（legacy 除外）。
2. 同一章所有 decision 的 `status` 只能是 pending/decided；`superseded` 不参与 gate。
3. `canon` 只能由 `beat_decide` / `beat_adjust` 改；`beat_compile`/`beat_verify` 只读。
4. `obligations` 只能由 `beat_decide` 新增、`beat_verify` 标记 paid、`beat_adjust` 标 waived。
5. 任何写操作都要 append 一条 `audit`。

## 5. 工具 API（7 个）

> 刻意不加 `beat_context`：它的职责由 `beat_list(context:true)`（规划前）和 `beat_compile`（写前）承担，少一份 schema、少一次往返。功能验收按「下一章能看到上一章状态」测，不按工具名测。
>
> `beat_adjust` 是作者主权动作，工具描述里写明「仅当作者明确要求时调用」。

### 5.1 `beat_plan`

**用途**：登记本章会改变状态的分叉；首访自动建书；返回待拍板清单 + 相关 canon/义务提醒。

**参数**
```json
{
  "dir": "绝对路径",
  "book": "书名",
  "chapter": 1,
  "beats": [
    {
      "title": "玉佩怎么到手",
      "kind": "得失",
      "change": "玉佩 从 拍卖品 变成 林砚持有",
      "options": [
        {
          "label": "拍卖会竞价拍下",
          "impact": "花钱得玉，得罪同场出价人…",
          "changes": [
            { "entity": "玉佩", "key": "持有者", "from": "拍卖行", "to": "林砚", "evidence": ["落槌"] }
          ],
          "obligations": [
            { "text": "同场出价人记恨林砚", "dueChapter": 3, "evidence": ["出价人"] }
          ],
          "forbidden": ["白送"]
        }
      ]
    }
  ],
  "append": false,
  "reset": false,
  "context": "可选：作者给这一段的创意原文"
}
```

**行为**
- `book.json` 不存在：创建（meta 从 title/genre/logline 或默认值）。
- 本章已有 `decided` 且 `append=false` 且 `reset=false`：拒绝，提示用 `append` 或 `beat_decide(supersede)`。
- `reset=true`：仅当本章没有 `decided` 决策；否则拒绝（不覆盖已拍板）。
- `append=true`：保留已拍板，新 id 从本章现有最大 n+1 开始。
- 校验：title/change 非空；change ≥4 字；options 2–4；label 唯一；每个 option 的 changes 非空；changes 的 `(entity,key,to)` 集合两两不同（伪分叉直接拒）。
- 冲突：若某 option 的 `(entity,key)` 与 canon 现值不同，返回 `warnings`（不拒；拍板时再硬判）。
- 返回：`{ total, pending, ids, path, warnings, context: { canon, obligations } }`（context 只带与本章 entity 相关的 canon + 到期/未回收义务，避免全书灌入）。

**错误码**：`bad-book`、`bad-chapter`、`empty-beats`、`too-few-options`、`too-many-options`、`duplicate-label`、`empty-changes`、`duplicate-changes`、`already-decided`、`reset-refused`。

### 5.2 `beat_list`

**用途**：看书/看章/看上下文。修 0.5 的 schema 不一致（描述说不传 chapter，但 `required` 含 chapter）。

**参数**：`dir`、`book`、`chapter?`、`onlyPending?`、`context?`。

**行为**
- 无 `chapter`、无 `context`：全书概览（章数、待拍板数、canon 条数、open/overdue 义务、最近 5 条决策）。
- 有 `chapter`：本章决策列表（含 status/chosen/legacy）。
- `context=true`：返回 canon（上限 200 条，超出截断并提示）+ open obligations（含 `dueChapter`、`overdue`）+ 最近 5 条决策；`chapter` 用于算 overdue。
- 返回统一 `{ book, chapters, decisions, canon, obligations, warnings, path }` 的按需子集。

### 5.3 `beat_decide`

**用途**：作者拍板；写 chosen、canon、obligations、audit。

**参数**：`dir`、`book`、`chapter`、`id`、`choice`、`changes?`、`note?`、`supersede?`、`reason?`。

**行为**
- `choice` 精确匹配某个 option.label：快照该 option 的 changes/obligations/forbidden。
- 不匹配：视为作者自定义，必须传 `changes`（非空，结构同上）；否则拒绝。
- 已 `decided`：
  - 同一 choice 且无 changes：幂等返回。
  - 不同 choice：必须 `supersede=true` + `reason`；否则拒绝。
- canon 冲突（同一 `(entity,key)` 现值 ≠ `to`）：
  - 若冲突 canon 的 `decisionId` 就是本决策：允许（重拍）。
  - 否则硬拒，列出冲突；提示先 `beat_adjust(supersede)` 那条旧决策。
- 写 canon：按 changes 逐条 upsert；`from` 提供了就校验现值是否等于 `from`，不等则冲突。
- 写 obligations：`text` 去重（同 text + 同 sourceDecision 幂等）；`dueChapter` 缺省为 null（长期开放）。
- 返回：`{ id, status, remaining, total, canonChanges, obligations, warnings }`。

**错误码**：`not-found`、`not-pending`、`need-supersede`、`custom-needs-changes`、`canon-conflict`、`bad-from`。

### 5.4 `beat_gate`

**用途**：写正文前的硬门禁（工具级）。

**参数**：`dir`、`book`、`chapter`。

**行为**
- 无决策：`pass=false`，message 提示先 `beat_plan`。
- 有 pending：`pass=false`，列出 pending 的 id/title。
- 全部 decided：`pass=true`；若存在 `legacy` 决策，附 warning「legacy 决策无结构化 changes，verify 只能弱校验」。
- 返回：`{ pass, total, pending, message, warnings }`。

### 5.5 `beat_compile`

**用途**：把已拍板决策编译成模型可执行的约束文本 + 机器可读 contract。

**参数**：`dir`、`book`、`chapter`、`format?`（`self` 默认 / `novel-forge`）。

**行为**
- 有 pending：返回 `missing`，不产出正式契约。
- `self` 输出：
```markdown
## 本章决策约束

### b1-1 玉佩怎么到手
- 已拍板：拍卖会竞价拍下
- 必须发生（正文至少出现一处证据）：
  - 玉佩：持有者 拍卖行 → 林砚（证据：落槌 / 玉佩入手）
  - 林砚：现银 充足 → 见底（证据：钱袋空了 / 最后一只银锭）
- 不得出现：白送 / 捡漏

## 本章必须回应的既有义务
- ob1 同场出价人记恨林砚（第 3 章前；证据：出价人 / 记恨）

## 全书 canon（不得违反）
- 玉佩.持有者 = 林砚（第 1 章，b1-1）
```
- `novel-forge` 输出旧格式（`## 本章必写场景` / `## 本章禁止偏离项`），并附 warning「deprecated，0.7 移除」。
- 返回：`{ markdown, contract, missing, warnings }`；`contract` 是 JSON（decisions/canon/obligations/forbidden），给 verify/debug 用。

### 5.6 `beat_verify`

**用途**：正文写完后的确定性校验；不读心，只查证据。

**参数**：`dir`、`book`、`chapter`、`text?`、`path?`、`strict?`（默认 true）。

**行为**
- `text`/`path` 二选一；`path` 必须工作区内 `.md`/`.txt`，≤2 MB。
- 检查：
  1. **required changes**：每个 decided 决策的每条 change，`evidence` 任一短语出现在正文 → 通过；否则若 `to` 值出现 → 通过但 warning `weak-evidence`；否则 failure `missing-change`。
  2. **forbidden**：任一短语出现 → failure `forbidden-hit`。
  3. **obligations due**：`open` 且 `dueChapter <= chapter`，`evidence` 任一出现 → 通过；否则 warning `obligation-due`（用户已确认 warning 档）。
  4. **legacy**：跳过 required changes，给 warning `legacy-weak`。
- `pass = failures.length === 0`；warning 不影响 pass。
- 通过：`chapters[chapter].status='verified'`、`verifiedAt`；失败不改状态。
- 返回：`{ pass, failures, warnings, stats: { decisions, changes, covered, forbiddenHits, obligationsDue } }`。

**错误码**：`no-text`、`path-outside`、`too-large`、`unreadable`。

### 5.7 `beat_adjust`

**用途**：作者改主意时的两个主权动作。

**参数**：`dir`、`book`、`action`（`waive`/`supersede`）、`id`、`reason`（必填）、`changes?`。

**行为**
- `waive`：义务 → `waived`，写 `waivedReason`，audit。若义务已 paid，拒绝。
- `supersede`：决策 → `superseded`；仅当它的 canon 条目没有被**更晚的决策**覆盖（否则拒绝，提示先处理更晚的）；删除它拥有的 canon 条目，audit。可选 `changes` 用于记录替代值，但不自动新建决策。
- 返回：`{ id, status, affectedCanon, warnings }`。
- 工具描述：仅当作者明确说「这条不要了/我要改」时调用。

## 6. 开关（会话级）

### 6.1 语义

- 粒度：**会话级**（不是全局）。默认 `off`（用户 m00430 定）：装上不主动占 schema，作者点按钮或 `/beat on` 才启用。
- 关：该会话的 `beat_*` 工具从 schema/lookup/execution 三处消失；不影响其他会话；数据保留。
- 开：恢复。
- resume：同 session id 恢复；fork 的新 session 默认 `off`（0.6 不做继承）。
- `/beat status` 返回 `on|off` + 当前书路径。

### 6.2 实现

- 状态文件：`<dir>/.dsh-novel-beat/_sessions.json`，`{ "<sessionId>": { "mode": "on", "updatedAt": "..." } }`。
- `<dir>` 取 agent 的工作目录（`ctx.workingDirectory` / agent 上下文）；拿不到时退回 `process.cwd()`。
- `agent/created`：拿 `agent.ctx`，读 mode；`off` 时 `agent.ctx.tools.restrict(...)` 隐藏 `beat_*`；保存 disposer。
- `/beat on|off`：改文件 → dispose 旧的 restrict → 重新 apply；返回新状态。
- 插件加载时对已存在的 agent 逐个 apply（`ctx.agents.list()`）。
- 如果 `restrict` 的过滤形状是谓词/名单，按 Host Service 定义实现；原则是「只移除，不新增；schema/lookup/execution 对齐」。
- `agent/created` 时序若早于工具注册，M4 实测后用 `agent/request` 首访兜底；不猜。

### 6.3 命令与远程通道（最终实现）

- `/beat on`、`/beat off`、`/beat status`：host 侧唯一实现；按钮的 `setMode` 也调这条命令，不双写。
- `ctx.remote.commands.execute` 方案实测失败：client 拿不到可用的 Agent 绑定，按钮停在 `remote 未就绪`。最终采用 Typert remote：
  - host `lib/remote.js`：`class BeatRemote extends TypertRemoteService`；`status(sessionId)` 读 `workingDirectory.ensure` + `getSessionMode`；`setMode(sessionId,on)` 用 `SessionId` 解析 agent，再 `ctx.commands.execute(agent, '/beat on|off', ...)`。
  - `lib/remote-contract.js`：`beatMode` 的 `status` / `setMode` descriptors；`TYPERT_REMOTE.package='dsh-novel-beat'`。

## 7. 端到端工作流

```text
作者：写第 N 章
  → 模型 beat_list(context:true)           # 看 canon + 未回收义务
  → 模型 beat_plan(...)                    # 登记分叉，2–4 个真选项
  → 模型 ask_user_question 逐个拍板
  → 模型 beat_decide(...) × N              # 写 chosen/canon/obligations
  → 模型 beat_gate(...)                    # 必须 pass
  → 模型 beat_compile(...)                 # 自包含契约
  → 模型写正文（宿主模型，不关插件的事）
  → 模型 beat_verify(text/path)            # 缺变化/禁项/义务到期
  → 不通过：改正文/重跑 verify
  → 通过：本章 verified；下一章从 canon 继续
```

作者改主意：
```text
beat_adjust(waive, ob1, "这条伏笔不要了")
beat_adjust(supersede, b3-2, "这个走向作废")
beat_decide(supersede:true, reason:"…")   # 重拍当前决策
```

## 16. M2 实现记录（2026-11-07）

> 本节是 M2 当时的状态（55 tests / 0.5.0）；最终状态见 §17。

已落盘并通过测试的实现，和 §5 的计划有 3 处刻意调整：

1. **`beat_context` 不单独注册**：职责拆进 `beat_plan` 的返回（本章相关 canon + 到期/未回收义务）和 `beat_list(context:true)`（全书 canon + open obligations + 最近 5 条决策）。工具仍是 7 个，schema 预算更稳。
2. **`applyChangesToCanon` 允许“合法推进”**：原计划写“canon 冲突硬拒”，实现细化为
   - `current.value === to` → noop；
   - `current.decisionId === 本决策` → 重拍；
   - `change.from` 存在且 `current.value === change.from` → 合法推进（更新 value/chapter/decisionId）；
   - 其余才算 `canon-conflict`。
   理由：`from` 与当前值一致是正常剧情推进，不是记错状态；只有 `from` 对不上当前值才该硬拒。测试 `test/schema.test.mjs` 已按此覆盖 conflict 与 transition 两条路径。
3. **`beat_verify` 的 `strict` 默认 true**：缺证据是 `missing-change` failure；`strict:false` 时降级为 warning，仍 pass。只命中 `to`、没命中 evidence 时给 `weak-evidence` warning 而不是 failure——这是确定性校验的边界，不冒充语义审稿。
